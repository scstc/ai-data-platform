# 字段映射功能使用说明

## 功能概述

在**数据湖抽取生成数据集**时，支持为每个快照配置**多个输出字段**，每个输出字段用模板从源列取值/拼接，适用于：

- **QA 对数据集**：`question` + `answer` → `text`
- **客服对话**：`user_query` + `assistant_reply` → `text`
- **多字段输出**：`{"id": "{order_id}", "text": "问:{question} 答:{answer}"}` 这类目标 schema
- **结构化转非结构化**：任意字段组合成 LLM 训练文本

**适用数据类型**：所有表格类数据
- 数据库表（PostgreSQL、MySQL、GoldenDB 等）
- CSV / TSV 文件
- Excel 文件（.xlsx、.xls）
- JSONL / JSON 文件

## 使用位置

**数据湖详情页 → 勾选快照 → 抽取生成数据集**

注意：字段映射功能在**数据湖抽取**环节，不在采集任务环节。

## 使用步骤

### 1. 进入数据湖详情页

路径：**数据治理 → 数据湖 → 点击某个数据湖**

### 2. 选择快照

在「文件列表」中勾选一个或多个快照（必须包含至少一个**表格类快照**）

**表格类快照**包括：
- `database` 类：数据库采集的数据
- `tabular` 类：CSV、TSV、Excel、JSONL 等文件

### 3. 点击「抽取生成数据集」

右上角按钮会显示已选快照数量

### 4. 填写表单

弹窗中包含以下字段：

- **数据集名称**（必填）
- **描述**（可选）
- **字段映射配置**（可选，仅当选中表格类快照时显示）
  - 列出所有表格类快照
  - 每个快照可单独配置字段映射模板

### 5. 配置字段映射（逐文件）

系统会列出所有表格类快照（database / tabular），每个快照显示：
- 文件名
- 数据类型标签
- 存储格式
- 输出字段行列表（默认一行 `text`，可增删行；模板留空的行不生效）

每行 = 一个输出字段：**输出字段名 + 取值模板**，模板中用 `{源字段名}` 占位符引用源列。

**逐文件配置的优势**：
- 不同文件的字段名不同，可以单独配置
- 某些文件不需要字段映射，可以留空
- 输出字段集合完全自定义（不再固定只产 `text`）

**示例场景**：

选中 3 个快照：
1. `qa_bank.csv` - 配置：`text` → `用户提问：{question}，客服回答：{answer}`
2. `银行交易明细.tsv` - 配置：`id` → `{order_id}`、`text` → `{summary}`（输出 `{"id":..., "text":...}`）
3. `customer_feedback.csv` - 留空（已有 text 字段，不需要映射）

### 6. 提交

点击「确定」，系统会：
1. 从快照中抽取原始数据
2. 应用字段映射（仅对 database 类快照）
3. 生成新数据集
4. 跳转到数据集详情页

## 数据转换示例

### 场景：多文件不同字段结构

假设选中了 2 个快照：

#### 快照 1：`qa_bank.csv`（PostgreSQL 采集）

**原始数据**：
```json
{
  "id": 1,
  "question": "农业银行手机银行单日转账限额多少？",
  "answer": "农业银行手机银行默认单日累计转账限额10000元..."
}
```

**配置模板**：
```
用户提问：{question}，客服回答：{answer}
```

**输出**（裁列为 text + meta，原始源列不落地）：
```json
{
  "text": "用户提问：农业银行手机银行单日转账限额多少？，客服回答：农业银行手机银行默认单日累计转账限额10000元...",
  "meta": {
    "src": "qa_bank",
    "date": "2026-07-03",
    "version": "source_v20260703_01_postgresql"
  }
}
```

#### 快照 2：`qa_insurance.csv`（CSV 上传）

**原始数据**：
```json
{
  "id": 101,
  "user_query": "保险理赔需要哪些材料？",
  "assistant_reply": "需要提供保单、身份证、理赔申请书..."
}
```

**配置模板**（不同字段名）：
```
用户提问：{user_query}，客服回答：{assistant_reply}
```

**输出**（裁列为 text + meta，原始源列不落地）：
```json
{
  "text": "用户提问：保险理赔需要哪些材料？，客服回答：需要提供保单、身份证、理赔申请书...",
  "meta": {
    "src": "qa_insurance.csv",
    "date": "2026-07-03",
    "version": "source_v20260703_02_csv"
  }
}
```

#### 快照 3：多输出字段（`id` + `text`）

**原始数据**：
```json
{"order_id": "A001", "question": "余额怎么查", "answer": "打开APP首页"}
```

**配置**（两行输出字段）：
- `id` → `{order_id}`
- `text` → `问:{question} 答:{answer}`

**输出**（裁列为 id + text + meta）：
```json
{
  "id": "A001",
  "text": "问:余额怎么查 答:打开APP首页",
  "meta": {"src": "...", "date": "...", "version": "..."}
}
```

### 总结

- 两个快照字段名不同（`question/answer` vs `user_query/assistant_reply`）
- 通过逐文件配置，可以为每个快照使用正确的字段名
- 输出字段集合自定义：单 `text` 可合并训练，也可产出 `{"id":..., "text":...}` 等多字段 schema

## 技术实现

### 后端流程

```
用户提交映射字典
    ↓
ExtractToDatasetRequest.field_mapping: dict[str, str | dict[str, str]]
  （value 为 {输出字段: 模板} 字典；旧格式单模板字符串等价于 {"text": 模板}）
    ↓
lake_extract.extract_to_new_dataset()
    ↓
遍历每个快照:
  - extract_from_lake_snapshot() 读取原始记录
  - 查找 field_mapping[snapshot.id]，归一为 {输出字段: 模板}
  - 如果是表格类快照 + 有映射
    → _apply_field_mapping_transform() 应用映射
  - add_table_member() 落地为数据集表成员
    ↓
返回新数据集
```

### 字段映射转换

纯 Python 占位符替换（`_render_template`，不经 DJ 算子 / eval）：

1. 正则匹配模板中的 `{字段名}` 占位符（`\{(\w+)\}`）
2. 每个占位符替换为源记录对应列的值（缺列 / None → 空字符串）
3. 每条记录产出 `{输出字段: 渲染结果}`，再拼回 `meta` 血缘
4. 模板中的引号、`{a.b}` 等非法占位符原样保留，不会被求值执行

输出字段名 `meta` 为保留字（血缘元数据专用），后端拒绝。

### 前端数据结构

表单值（每快照一个行列表）：
```typescript
{
  datasetName: "QA数据集",
  description: "银行+保险QA",
  fieldMappings: {
    "snapshot-abc123": [
      { field: "text", template: "用户提问：{question}，客服回答：{answer}" }
    ],
    "snapshot-def456": [
      { field: "id", template: "{order_id}" },
      { field: "text", template: "问:{question} 答:{answer}" }
    ]
  }
}
```

提交时行列表转字典，跳过字段名/模板为空的行；整快照无有效行则不发送该快照的映射。

### 条件判断

- **仅对 database 类快照生效**：文件类（图片、文档等）无固定 schema，跳过
- **前端条件渲染**：仅当选中的快照中至少有一个 `dataCategory === 'database'` 时，才显示字段映射表单

## 限制与注意事项

1. **仅表格类快照生效**
   - **database 类**：采集任务从数据库拉取的数据
   - **tabular 类**：CSV、TSV、Excel、JSONL 等表格文件
   - 其他类型（图片、音频、视频、文档）会跳过字段映射

2. **字段名大小写敏感**
   - `{Question}` 和 `{question}` 是不同的字段

3. **裁列落地（DJ 标准格式）**
   - 配置了映射的快照，落地记录只保留**映射的输出字段** + `meta`
   - `question/answer` 等原始源列不落地；未配置映射的快照保留全部原字段 + `meta`
   - 输出字段名 `meta` 为保留字，不允许映射覆盖
   - `meta` 仅含 DJ 三元组 `src`（原文件名/源表名）/ `date`（入湖日期）/ `version`（快照版本号）；`version` 可反查数据湖快照追溯完整血缘（快照 ID、上传渠道、库表/桶等）

4. **模板长度限制**
   - 前端限制 500 字符

5. **字段不存在时**
   - 自动填空字符串（`row.get("字段", "")`）
   - 不会报错

6. **混合快照**
   - 如果选中的快照既有表格类又有媒体类
   - 仅表格类会应用字段映射
   - 媒体类正常抽取（不受影响）

## 常见问题

### Q：字段映射在哪个环节生效？

A：在**数据湖抽取生成数据集**环节，不是采集任务环节。

### Q：如何知道快照有哪些字段？

A：数据湖详情页可以预览快照内容，查看字段列表。或者参考原始数据源的表结构。

### Q：可以对文件类快照使用字段映射吗？

A：可以！只要是**表格类数据**都支持：
- ✅ 数据库表（database 类）
- ✅ CSV、TSV 文件（tabular 类）
- ✅ Excel 文件（tabular 类）
- ✅ JSONL、JSON 文件（tabular 类）
- ❌ 图片、音频、视频（无字段结构）
- ❌ PDF、Word、PPT 文档（非结构化）

### Q：选中多个快照，每个快照的字段不一样怎么办？

A：**逐文件配置**功能就是为了解决这个问题！

UI 会列出所有表格类快照，每个快照可以单独配置模板。

**示例**：
- 快照 A 字段：`question`、`answer` → 配置：`用户提问：{question}，客服回答：{answer}`
- 快照 B 字段：`user_query`、`assistant_reply` → 配置：`用户提问：{user_query}，客服回答：{assistant_reply}`
- 快照 C：已有 `text` 字段，留空不配置

### Q：可以只为部分快照配置字段映射吗？

A：可以！每个快照的模板输入框都是可选的，留空表示不对该快照应用字段映射。

### Q：原字段会被删除吗？

A：配置了映射的快照会**裁列**：落地只保留映射的输出字段 + `meta`，原始源列不落地。想保留某个原字段，就为它加一行映射（如 `id` → `{id}`）。未配置映射的快照保留全部原字段。

### Q：可以用多行模板吗？

A：可以。模板支持换行符，输出的 `text` 字段会保留换行。

## 代码位置

### 后端

- **Schema**：`backend/app/schemas/data_lake.py` — `ExtractToDatasetRequest.field_mapping`
- **服务层**：`backend/app/services/lake_extract.py`
  - `extract_to_new_dataset()` — 主流程
  - `_apply_field_mapping_transform()` — 字段映射转换
- **路由**：`backend/app/api/v1/data_lakes.py` — `POST /data-lakes/{lake_id}/extract-to-dataset`

### 前端

- **类型定义**：`frontend/src/services/data-platform/api.ts` — `extractLakeToDataset` body 类型
- **UI 表单**：`frontend/src/pages/data-lakes/detail.tsx` — 抽取弹窗
