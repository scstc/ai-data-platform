## 实际效果演示

### 用户操作流程

1. **新建采集任务**
   - 选择数据库类型数据源
   - 在 step-2 选择表或填写 SQL
   - 进入 step-3「落地确认」

2. **配置字段映射**
   - 页面自动显示「可用字段」Tag 列表（如：`id`、`question`、`answer`）
   - 点击字段名（如 `question`），自动插入 `{question}` 到模板
   - 填写完整模板：`用户提问：{question}，客服回答：{answer}`

3. **数据转换**
   - 采集执行时，记录自动新增 `text` 字段
   - 原字段保留（`id`、`question`、`answer`）

### 技术流程

```
用户填写模板 "用户提问：{question}，客服回答：{answer}"
    ↓
前端提交 extract.fieldMapping
    ↓
后端 _apply_field_mapping() 转换
    ↓
生成 python_lambda_mapper 算子
lambda row: {**row, 'text': f'用户提问：{row.get("question", "")}，客服回答：{row.get("answer", "")}'}
    ↓
插入 extract.operators 头部
    ↓
采集执行：fetch → apply_filter_operators（执行 lambda）→ land
    ↓
落地记录新增 text 字段
```

## 设计亮点

1. **零核心逻辑改动**
   - 复用现有 `apply_filter_operators` 和 `python_lambda_mapper`
   - 不侵入 landing / connector 核心代码

2. **配置即代码**
   - 模板存储在任务配置中
   - 自动转换为可执行算子
   - 可随时修改、立即生效

3. **用户体验优化**
   - 自动获取字段列表（不用盲猜字段名）
   - 点击即插入（不用手打 `{}`）
   - 实时预览（选表后立即显示字段）

4. **安全性**
   - `row.get("字段", "")` 防止 KeyError
   - 模板字面量正确转义
   - 长度限制（500 字符）

## 已知限制

1. **仅数据库采集生效**
   - S3/HDFS 文件类无固定 schema，不支持字段映射
   - 前端 UI 已按数据源类型条件渲染

2. **字段获取依赖预览 API**
   - 如果 `previewIngestSource` 失败，字段列表为空
   - 不影响表单提交（用户可手动填写）

3. **字段刷新时机**
   - 仅在 `onValuesChange` 触发时刷新
   - 如果采集对象配置复杂，可能需要手动刷新
