
# AI多源数据治理与标准化数据集生产平台PRD
## 1. 文档概述
### 1.1 产品目标
搭建**多源统一数据湖+标准化算子加工流水线**，实现异构数据源统一接入、版本归档、血缘追踪，自动化生产AI全品类标准化数据集（预训练、SFT、RLHF、多模态），满足大模型训练、微调、评测全场景数据需求，同时符合企业数据治理、审计溯源规范。

### 1.2 适用范围
覆盖全业务数据源：国产数据库、通用数据库、MinIO/S3、阿里云OSS、华为OBS、本地上传文件、API推送文件；
覆盖全数据形态：结构化数据表、Word/PDF/Excel/PPT文档、图片、音频、视频；
覆盖全AI数据集产出规格。

### 1.3 核心设计理念
1. **湖集分离**：原始异构数据入数据湖（仅归档、不加工），加工标准化后生成正式AI数据集；
2. **全链路血缘**：所有数据自带版本、来源元数据，全程透传可追溯；
3. **统一流水线**：基于Data-Juicer实现通用算子清洗，多源数据统一归一化；
4. **格式标准化**：所有品类AI数据集统一JSONL输出，兼容模型训练生态。

## 2. 整体系统架构（分层规范）
严格四层架构，杜绝概念混淆，适配数据治理标准：

### 2.1 第一层：多源数据湖（ODS原始层）
#### 核心定义
外部所有异构数据源**原样接入、原样存储**，仅做版本快照归档，**不属于数据集**，是所有AI数据的原始原料池。

#### 接入数据源清单
1. 数据库类：MySQL、PostgreSQL、达梦、人大金仓、OceanBase等国产/通用数据库
2. 对象存储类：MinIO（S3兼容）、阿里云OSS、华为OBS
3. 文件类：本地手动上传文件、API接口推送文件
4. 多媒体类：图片、音频、视频原始文件

#### 数据湖存储规范
1. 结构化数据库数据：统一导出为**Parquet**列式文件入湖，保留原始表结构
2. 文档/多媒体数据：Word、PDF、Excel、PPT、jpg、mp3、mp4等**原格式入湖**
3. 核心规则：原始数据只读归档、永不覆盖、版本固化、永久溯源

#### 数据湖核心能力
负责**唯一对外交互**，承接所有外部系统、文件、接口的数据接入，是系统唯一数据入口。

### 2.2 第二层：数据抽取与前置解析层
从数据湖中按需筛选、抽取指定版本、指定类型的原始数据，完成格式解析与初步结构化，生成统一中间JSONL分片文件。

#### 解析规则
1. 数据库Parquet：读取表字段，拼接为自然业务文本，注入数据库血缘元数据
2. 办公文档（Word/PDF/Excel/PPT）：解析正文、表格、章节，拆分为规范文本块
3. 图片：提取图文描述、标注文本，绑定存储路径
4. 音频：语音转写（ASR），生成文本字幕，绑定音频路径
5. 视频：提取字幕、关键帧描述，绑定视频存储路径

#### 输出产物
带完整血缘、版本元数据的**中间分片JSONL文件**（未最终清洗，非成品数据集）

### 2.3 第三层：Data-Juicer算子加工层（核心加工层）
所有中间JSONL统一进入Data-Juicer流水线，通过可插拔算子完成标准化治理清洗，**仅处理文本内容，所有血缘元字段全程透传保留**。

#### 通用算子流水线（固定顺序）
1. 基础清洗：空值、乱码、特殊符号、无效文本清理
2. 合规治理：敏感信息脱敏、违规内容过滤
3. 质量过滤：长短文本筛选、低质量文本剔除
4. 去重处理：单分片/全局跨分片去重
5. 文本规整：切块、格式统一、字段校准

### 2.4 第四层：标准化AI数据集成品层
算子加工完成后，输出**可直接用于大模型训练/微调/评测**的标准化成品数据集，对内供给模型业务，不再对接外部原始数据源。

## 3. 版本与血缘体系（治理核心）
### 3.1 双版本机制
1. **源头快照版本（source_v）**
   - 格式：`source_v年月日_批次_数据源类型`
   - 作用：固化数据湖原始原料，锁定源头所有数据，永久不可修改
2. **加工成品版本（dataset_v）**
   - 格式：`dataset_v序号`
   - 作用：记录每一轮算子流水线加工版本，规则迭代升级不覆盖旧数据

### 3.2 全局通用血缘字段（全数据集透传）
所有品类JSONL数据集，强制携带以下元字段，Data-Juicer不删除、不覆盖：
```json
{
  "source_version": "源头快照版本号",
  "process_version": "数据集加工版本号",
  "source_category": "database/file/media",
  "upload_channel": "oss/obs/minio/api/local",
  "chunk_uuid": "唯一分片ID",
  "dj_task_id": "Data-Juicer任务ID"
}
```

### 3.3 差异化溯源字段
1. 数据库数据：附带 `db_schema、db_table、db_engine`
2. 对象存储数据：附带 `bucket_name、obj_key`
3. 本地/API文件：附带 `original_filename`

## 4. 全品类数据集标准化JSONL格式（Data-Juicer全兼容）
所有格式**原生支持Data-Juicer流水线**，仅清洗文本字段，结构、血缘完整保留。

### 4.1 预训练数据集（基座预训练/增量预训练）
#### 适用场景：大模型底座通用训练、行业增量预训练
#### 标准格式
```json
{"text": "纯文本段落内容", "source_version": "xxx", "process_version": "xxx"}
```
#### 特点：无问答、无指令，纯连续文本，适配预训练任务

### 4.2 SFT微调数据集（单轮Alpaca格式）
#### 适用场景：通用指令微调、行业能力对齐
#### 标准格式
```json
{
  "instruction": "用户指令/问题",
  "input": "上下文信息（可为空）",
  "output": "模型标准回答",
  "source_version": "xxx"
}
```

### 4.3 SFT多轮对话数据集（ShareGPT格式）
#### 适用场景：聊天对话模型微调
#### 标准格式
```json
{
  "messages": [
    {"role": "user", "content": "用户提问"},
    {"role": "assistant", "content": "模型回答"}
  ],
  "source_version": "xxx"
}
```

### 4.4 RLHF/DPO偏好数据集
#### 适用场景：奖励模型训练、人类偏好对齐
#### 标准格式
```json
{
  "prompt": "用户问题",
  "chosen": "优质标准答案",
  "rejected": "劣质负样本回答",
  "source_version": "xxx"
}
```

### 4.5 多模态数据集（图/音/视频）
**核心规则：多媒体原始文件留存数据湖，数据集仅存储对象存储路径，不嵌入二进制文件**

1. 图片数据集
```json
{"image": "minio/oss/obs文件路径", "text": "图片描述/问答文本", "source_version": "xxx"}
```
2. 音频数据集
```json
{"audio": "oss文件路径", "transcript": "语音转写文本", "source_version": "xxx"}
```
3. 视频数据集
```json
{"video": "obs文件路径", "subtitle": "视频字幕/内容描述", "source_version": "xxx"}
```

## 5. 完整端到端业务数据流
外部多源数据 → **数据湖原样归档（版本固化）**
→ 按需抽取湖内数据 + 前置格式解析
→ 生成多源中间JSONL分片
→ Data-Juicer算子流水线统一清洗治理
→ 输出**预训练/SFT/RLHF/多模态**标准化成品数据集
→ 供给大模型训练、微调、评测业务

## 6. 核心业务规则总结
1. **湖集分离**：数据湖=原始原料（不可用训练），数据集=加工成品（可直接训练）
2. **外湖内集**：数据湖对接所有外部数据源，成品数据集仅对内模型服务
3. **全程溯源**：所有数据双版本标记，血缘字段全链路透传
4. **统一加工**：所有异构数据最终归一为JSONL，适配一套Data-Juicer流水线
5. **介质隔离**：音视频图片原始文件存湖，数据集仅记录路径，轻量化可复用
