# 算子模型依赖盘点

> 2026-07-10 · 基于 `backend/app/data/operators_catalog.json`（212 个可见算子）逐参数扫描 + data-juicer 源码交叉核验（`data_juicer/ops/` grep `model_type=`）。
> 目的:回答「哪些算子依赖模型、模型从哪来、治理收口该落在哪」。

## 一、结论速览

212 个可见算子中,涉及模型的共约 **104 个**,按模型来源分三大类:

| 类 | 数量 | 模型来源的"单一事实" | 收口手段 |
|---|---|---|---|
| A. API 模型 | 33 | LLM 配置中心（`resolve_llm_config`） | 隐藏 `api_model`/`api_endpoint` 表单项,注入逻辑已有（`engine.build_config`） |
| B. 本地显式模型 | 43 | 本地模型仓库（`DATA_JUICER_EXTERNAL_MODELS_HOME`,即 `deploy/download_dj_models.py` 预灌目录） | 表单只暴露仓库已有模型,缺则 fail-loud |
| C. 隐式模型 | 28 | 代码写死,平台侧无参数可改 | 只能靠预下载脚本清单覆盖;离线部署漏项运行期才暴露 |

其余 ~108 个为规则/统计类算子,不加载任何模型。

GPU 门控口径（`operator_catalog.effective_runnable`,operator_catalog.py:446-457）:
`resource_class ∈ {gpu(30), hf_model(28)}` 需 CUDA;`vllm(4)` 需 vLLM 服务或 CUDA+HF 回退;`api_llm(28)` 只需 LLM 配置,**不需要卡**;`cpu(122)` 永远 ready。

## 二、A 类:需要 API 模型（33 个）

模型名由平台注入:`engine.build_config` 对参数表含 `api_model`/`api_or_hf_model` 且用户未显式填写的算子,注入 LLM 配置中心激活配置的模型名;api_key/base_url 经 `_subprocess_env` 环境变量注入（正式任务 base_url 指向 `/api/v1/llm-proxy/{job_id}` 计量转发）。

### A1. 纯 API 型（`api_model` 参数,内置 19 + 自定义 2）

- calibrate 系列（3）:`calibrate_qa_mapper` / `calibrate_query_mapper` / `calibrate_response_mapper`
- dialog 系列（4）:`dialog_intent_detection_mapper` / `dialog_sentiment_detection_mapper` / `dialog_sentiment_intensity_mapper` / `dialog_topic_detection_mapper`
- extract 系列（6）:`extract_entity_attribute_mapper` / `extract_entity_relation_mapper` / `extract_event_mapper` / `extract_keyword_mapper` / `extract_nickname_mapper` / `extract_support_text_mapper`
- aggregator 系列（4）:`entity_attribute_aggregator` / `meta_tags_aggregator` / `most_relevant_entities_aggregator` / `nested_aggregator`
- 其他（2）:`pair_preference_mapper` / `relation_identity_mapper`
- 自定义算子（2,`uploads/custom_operators/`）:`generate_cot_mapper` / `generate_sft_mapper`

### A2. API/本地双模（`api_or_hf_model` + `is_hf_model`/`is_api_model` 开关,12 个）

`llm_analysis_filter` / `llm_condition_filter` / `llm_difficulty_score_filter` / `llm_quality_score_filter` / `llm_task_relevance_filter` / `llm_extract_mapper` / `text_embd_similarity_filter` / `image_tagging_vlm_mapper` / `optimize_prompt_mapper` / `optimize_qa_mapper` / `optimize_query_mapper` / `optimize_response_mapper`

默认 API 模式（不需要卡）;切 `is_hf_model=true` 走本地 HF 推理（需要卡）。**收口时需决策是否保留本地模式**——参数是双语义的,硬灌 API 模型名会堵死本地 vLLM 场景。

## 五、需要显卡的算子(按守门口径,共 62 个)

- `resource_class=gpu`(30):B3 全部 + C1 大部分（RAM++/RAFT/OCR/相机位姿/手部重建/detect/imgdiff/pipeline 等）+ `instruction_following_difficulty_filter` / `in_context_influence_filter` / `optimize_query_mapper` / `optimize_response_mapper`
- `resource_class=hf_model`(28):B1 部分 + B2 全部（含两个"误伤",见下）
- `resource_class=vllm`(4):B1 的 generate/tagging/vlm-caption 四个,vLLM 在线或 CUDA+HF 回退即 ready

**已知分类偏差（未整改,仅记录）**:
- `alphanumeric_filter` / `token_num_filter` 只用 HF tokenizer 数 token（CPU 足够）,但被归入 hf_model 类,无卡环境显示 needs_compute,偏严。
- `calibrate_query_mapper` / `calibrate_response_mapper` / `llm_difficulty_score_filter` / `llm_quality_score_filter` / `llm_task_relevance_filter` 的 resource_class 是 cpu,但实际要调 LLM——LLM 未配置时不会被 needs_api 拦截,提交后运行期才失败,偏松。

## 六、治理收口要点（对应 LLM 配置中心收口讨论）

1. **A 类收口改动面极小**:注入逻辑已存在（`build_config`,engine.py:203-215）,只需在目录出参/前端表单隐藏 `api_model`、`api_or_hf_model`、`api_endpoint` 三个参数（19+12+30 处出现,一处过滤全体生效）,DJ 仓库与算子代码零改动。
2. **A2 的 12 个双模算子需要豁免决策**:是否保留 `is_hf_model` 本地模式。
3. **`api_endpoint` 是计量旁路**:用户显式填绝对 endpoint 可绕开 llm-proxy,收口时应一并隐藏。
4. **`filter_records`（采集内联过滤）是残留缺口**:不带 job_id、直连真实 base_url,不计量;且 DJ 侧 `_maybe_remap_model_for_dashscope`（fork 定制,model_utils.py:390）在 base_url 像 DashScope 且模型名非 qwen/deepseek 时会静默改名——这是唯一可能「实际调用模型 ≠ llm config 模型」的路径。
5. **自定义算子上传校验可加规则**:API 型算子模型参数必须命名 `api_model`,否则注入覆盖不到;存量 2 个已合规。
6. **C 类是离线部署最大风险**:无参数可查,预下载清单(`deploy/download_dj_models.py`)必须与 DJ 源码硬编码模型对齐,漏项只能运行期暴露。

## 七、数据来源与更新方式

- 目录快照:`backend/app/data/operators_catalog.json`（构建脚本 `backend/scripts/build_operator_catalog.py`);DJ 算子大版本升级后需重跑构建脚本并同步本文。
- 隐式统计模型清单来自源码 grep:`data-juicer/data_juicer/ops/` 内 `model_type="fasttext|kenlm|sentencepiece|spacy|nltk"`。
- C1 的具体模型名多为代码内常量/下载逻辑,本文只列算子与模型家族,精确模型名以 `data_juicer/utils/model_utils.py` 各 `prepare_*` 函数为准。
