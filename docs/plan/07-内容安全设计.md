# 07 · 内容安全审核(#4)设计

> 关联:需求 #4(数据内容安全)· [00-实现任务清单](00-实现任务清单.md) B 段。
> 状态:已与用户定稿(2026-06-15),4 个关键决策见下。待实现。

## 1. 范围

**做**:对数据集版本跑**内容审核任务**(独立 `type=review` job),检测 4 路并行——
①自定义敏感词/正则(UI 可配)②LLM 审核(DeepSeek 分 黄/赌/毒/政/恐)③内置敏感词表(对齐 DJ `flagged_words_filter` 语义,代码侧匹配)④PII 模式识别(Presidio 思路)。命中后**仅打标**:产出带 `safety` 字段的新版本(不删行),并落**审核记录**(可查可筛)+ **审核报告**。独立"内容安全"一级菜单。

**本期不做**:删除处置(仅打标)、NSFW 图/视频(needs GPU,承诺支持)、完整 Presidio spaCy NER(服务器资源/外网受限,用 pattern recognizer 子集替代)、等保级。

## 2. 数据模型(迁移 0007,down_revision=`0006_auth_audit`)

- **复用 `jobs`**:新 `type=review`。审核 job 产出一个新 `DatasetVersion`(打标版本,`origin="review"`,`produced_by_job_id`=job.id);血缘走既有 `job_input`(被审版本→review job)。
- **新表 `review_findings`**(逐条命中,可分页查):
  - `id`(`rf-`+hex)/ `job_id`(index)/ `version_id`(被审版本)/ `row_index`(int)/ `category`(`porn|gambling|drugs|politics|terrorism|pii|other`)/ `severity`(`high|medium|low`)/ `source`(`keyword|regex|flagged_words|llm|pii`)/ `detail`(命中词/正则名/LLM 理由/PII 类型)/ `snippet`(命中文本片段,截断 ~200 字)/ `created_at`(index)。
- **打标产物**:新版本 jsonl 每行加字段 `safety`:`{flagged:bool, categories:[...], maxSeverity, sources:[...], hits:[{source,category,detail}]}`;未命中行 `safety.flagged=false`。
- **审核报告**:存为 job 的 `review_report` JSON(像 quality 的 stats):`{totalRows, scannedRows, flaggedRows, sampleLimitApplied:bool, byCategory:{...}, bySeverity:{...}, bySource:{...}}`。写到 job 记录(新增列或复用既有 JSON 列;若无则迁移加 `jobs.review_report JSONB nullable`)。

## 3. 后端

### 3.1 审核引擎 `app/services/review.py`(自研,不走 dj-process)
逐行扫描被审版本 jsonl(取文本字段,优先 `text`,否则首个 str 字段),四路 source 汇总成 findings:
- **rules**:用户 `customWords`(子串/大小写不敏感)+ `customRegex`(命名正则,逐条 try,坏正则跳过)+ **内置词表** `app/data/sensitive_words.json`(按 category 组织,seed 一份精简演示词库;对齐 `flagged_words_filter` 语义)。命中 → finding(source=keyword/regex/flagged_words,category 取自词表/规则)。
- **pii** `app/services/pii.py`(Presidio 思路 pattern recognizer,纯正则,无第三方依赖):身份证(18 位)、手机号(`1[3-9]\d{9}`)、邮箱、银行卡(13–19 位)、IPv4。命中 → finding(source=pii,category=pii,detail=PII 类型)。
- **llm** `app/services/ai/` 增 `moderate_texts(texts) -> [{flagged,category,severity,reason}]`:DeepSeek 分批(每批 ~20 行)分类 黄/赌/毒/政/恐/正常 + 理由,返回 JSON 数组;解析失败/超时 → 该 source 整体跳过(降级,其余 source 仍出结果)。复用 `get_ai_provider()`/`OpenAICompatProvider`。
- **样本上限**:`sampleLimit`(默认 500,UI 可调)。超过则只扫前 N 行,`report.sampleLimitApplied=true`(**不静默截断**,报告/UI 显式标注);打标版本对未扫行 `safety.flagged=false` 且标 `scanned:false`。

### 3.2 任务编排 `app/services/review_runner.py`
load 版本 jsonl → 跑 `review.py` → 写 `review_findings` → 产出打标新版本(jsonl 加 `safety`,落 `datasets_dir/<dataset_id>/v<n>/data.jsonl`,注册 `DatasetVersion`,沿用 process job 产版本的写法)→ 汇总 `review_report` 回写 job → job `success`。复用既有引擎并发信号量;失败置 job `failed` + error。

### 3.3 API `app/api/v1/content_safety.py`(prefix /api/v1)
- `POST /content-safety/jobs`:body `{datasetVersionId, name?, config:{categories:[...], customWords:[...], customRegex:[{name,pattern}], useLlm, usePii, useFlaggedWords, sampleLimit?}}` → 建 job(type=review)+ 后台跑(同既有 job 异步模式)→ 返回 job。**不加 require_admin**(审核属分析类,#5 矩阵允许 user 试跑/分析;但 POST 会被审计中间件记录)。
- `GET /content-safety/jobs`:列 type=review 的 job(分页)。
- `GET /content-safety/jobs/{id}/report`:返回 `review_report` + job 状态 + 打标版本 id。
- `GET /content-safety/jobs/{id}/findings`:分页 review_findings,过滤 `category/source/severity`,按 row_index 升序。
- 状态轮询复用 `GET /jobs/{id}`。
- main.py include_router。

## 6. 风险 / 取舍

- **PII**:用正则 pattern recognizer(Presidio 思路),覆盖结构化 PII;完整 Presidio spaCy NER(姓名/地址等非结构化)因服务器资源 + 外网受限**延后**,文档标"承诺支持"。
- **LLM 成本/时延**:批量 + `sampleLimit` 兜底;失败降级到规则+PII。大数据集默认只扫样本并显式标注。
- **打标版本膨胀**:`safety` 字段加在每行;演示量级可接受。
- **权限**:审核任务不门控(分析类);打标产版本是写,但属演示核心流程,经审计中间件留痕。

## 7. 验收

- 选含违规/PII 样例的版本跑审核:报告显示各类别·来源命中数,明细可按类别筛;产出打标版本(`safety` 字段);findings 落库可查。
- 关掉 LLM(或 LLM 不可用)仍能靠规则+内置词表+PII 出结果(降级)。
- `sampleLimit` 生效时报告/UI 明确标注"仅扫描前 N 行"。
