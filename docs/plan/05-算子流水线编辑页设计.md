# 05 · 算子流水线编辑页(Pipeline Editor)设计

> 关联:[04-算子市场设计](04-算子市场设计.md) · [03-架构设计](03-架构设计.md) · [02 集成调研](02-data-juicer-集成与并发调研.md)
> 状态:已与用户头脑风暴定稿(2026-06-15),待评审 → 实现计划。

## 1. 背景与问题

当前"新建加工任务"是一个**模态 + 多选下拉**(`frontend/src/pages/processing/index.tsx`):
算子用 `ProFormSelect mode="multiple"` 勾名字,参数表单平铺在下方,顺序即多选顺序、不可拖拽调整,无流水线可视化、无预览。可用性弱(用户原话:"算子编排这块设计有点 low")。

**关键约束**:data-juicer 的 `process` 是一条**线性有序算子列表**(按序作用于同一数据集),**不是带分叉/合并的 DAG**(见 `backend/app/services/engine.py` 的 `build_config`)。因此正确抽象是**有序流水线步骤编辑器**,而非节点连线画布——画布的分叉是假的,引擎不支持。

## 2. 目标与范围

**做**:
- 新增整页 `/processing/editor`,**取代**现模态,提供:从算子库添加、拖拽排序、逐步配参、实时 YAML 预览、选数据集+版本后创建任务。
- AI 生成流水线:据数据集/目标场景,用 LLM 一键给出一串算子+参数(用户可再改)。

**本期不做(YAGNI)**:样例试跑(dry-run)、可复用模板、节点连线画布。

## 3. 入口与导航

- 加工任务列表页(`/processing/jobs`)「新建任务」按钮 → 跳 `/processing/editor`。
- 算子市场(`/operators`)购物车「去新建加工任务」→ 跳 `/processing/editor`(带入已选算子)。
- 加工任务是**不可变运行记录**,编辑页仅用于**新建**,不编辑历史任务。
- 路由:`frontend/config/routes.ts` 在 `/processing` 组下新增 `/processing/editor`;菜单 i18n 复用现有 `menu.processing.*`(编辑页可不进菜单,仅按钮/购物车进入)。

## 4. 页面布局(三栏 + 顶/底)

```
顶部: 任务名[____]  数据集[v] 版本[v]        [✨AI 生成] [创建任务]
┌ 算子库 ───────┐┌ 流水线(有序·可拖拽) ┐┌ 选中步骤·参数 ┐
 搜索▢ 场景▾     │ ⋮⋮ 1 中文繁简转换  × │ mode    [t2s ▾]
 只看可运行 ☑    │ ⋮⋮ 2 文本长度过滤  × │ min_len [10]
 ──────────     │ ⋮⋮ 3 MinHash 去重  × │ max_len [—]
 繁简转换    [+] │                      │ (按算子 params 渲染)
 长度过滤    [+] │  空态:从左侧添加算子  │
└───────────────┘└──────────────────────┘└───────────────┘
底部: YAML 预览(实时,与引擎 build_config 同构,只读)
```

- **左栏(算子库)**:复用算子市场数据源 `GET /api/v1/operators/catalog`,支持搜索 / 场景分面 / 「只看可运行」。点 `[+]` 或拖入中栏。默认只显示 `runnable==ready`(可切换)。
- **中栏(流水线)**:有序步骤列表,拖拽排序,点选某步在右栏配参,可删除。空态引导。
- **右栏(参数)**:按选中算子的 `params`(name/type/default/desc)动态渲染表单(select/number/switch/string)。
- **底部(预览)**:实时把 `{project_name, dataset_path, np, export_path, process:[{op:params}]}` 同构渲染为 YAML(前端只读、信息性;真实 YAML 仍由后端 `build_config` 运行时生成)。

## 5. 组件与状态

| 单元 | 职责 | 依赖 |
|------|------|------|
| `pages/processing/editor/index.tsx` | 编辑页容器:三栏布局 + 顶/底 + 创建提交 | catalog API、jobs API、opCart |
| `OperatorLibrary`(左) | 检索/分面/添加算子 | `listOperatorCatalog` |
| `PipelineSteps`(中) | 有序步骤渲染 + 拖拽排序 + 选中/删除 | `@dnd-kit/sortable` |
| `StepParamsForm`(右) | 按 params 定义渲染表单 | 选中步骤的 catalog 项 |
| `YamlPreview`(底) | 步骤序列 → YAML 文本 | 步骤状态 |

**状态**:把现有全局模型 `models/opCart.ts` 从"仅存名字 `string[]`"升级为**有序步骤** `{ name: string; params: Record<string, unknown> }[]`,作为市场→编辑页的数据载体;市场「加入」push 一个空参数步骤,编辑页据此继续增删、排序、配参。提供 `setSteps/add/remove/reorder/updateParams/clear`。

## 6. AI 生成流水线

- 新增后端 **`POST /api/v1/ai/generate-pipeline`**
  - 入参:`{ datasetVersionId?: string, goal: string }`(goal 为目标场景文本,如"中文语料清洗去重")。
  - 实现:把**可运行算子(`runnable==ready`)目录 + 各自参数**作为上下文喂 LLM,要求只输出目录内算子、合法参数、合理顺序;**代码侧校验**(算子存在且 `runnable==ready`、参数名在该算子 params 内)后返回 `{ operators:[{name, params}], explanation }`。
  - 无 LLM 配置时**回退启发式**(按 goal 关键词匹配 `scenario_group` 给一串默认 ready 算子),与现有 `app/api/v1/ai.py` 的"LLM 失败→启发式"模式一致。
- 前端:点「✨AI 生成」(可附 goal 输入)→ 结果填入中栏(覆盖/追加二选一,默认覆盖),展示 explanation;用户可继续编辑。

## 7. 创建任务与守门

- 创建仍走现有 `POST /api/v1/jobs`(入参 `{name, datasetVersionId, operators:[{name,params}]}`),后端既有的算子存在性校验 + `runnable_reason()` 资源前置校验**保持不变**(多一道保险)。
- 前端创建前校验:已选数据集+版本、至少 1 个算子、各步必填参数已填。
- 创建成功后:清空 opCart,跳回 `/processing/jobs`。

## 8. 取舍与默认决策

1. **取代旧模态**(而非并存):统一入口,避免两套编排 UI。
2. **YAML 预览前端渲染**(不加后端预览接口):预览仅信息性,真实 YAML 运行时由 `build_config` 生成,前端同构即可,避免重复后端逻辑。
3. **拖拽用 `@dnd-kit`**:与 antd v6 / React 19 兼容良好,体积可控。

## 9. 风险

- **参数类型覆盖**:catalog 的 params 来自文档解析,个别复杂类型(list/dict)前端表单先按字符串/JSON 文本兜底,不阻塞主流程。
- **AI 输出可信度**:LLM 可能给出不存在算子或非法参数 → 已用代码侧白名单校验拦截,非法项丢弃并在 explanation 标注。
- **opCart 结构升级**:需同步改算子市场页「加入」逻辑(push 步骤对象而非字符串),属本期内修改。
