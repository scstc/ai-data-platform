## 0. 终点契约:所有接入都通往不可变版本

不管数据从哪来(上传 / 数据库 / S3 / HDFS / API 推送 / 三方托管),接入的最终产物都是一个**不可变 `DatasetVersion`**。版本只有两种物理归宿——这是整个接入体系的地基分界线:

| `origin` | 含义 | 字节落点 | 能删吗 |
|---|---|---|---|
| **`managed`** | 平台拥有**物化副本**(已下载 + 归一化/拷贝) | 本地 `datasets_dir/<id>/v<N>/` 或 平台 MinIO `uploads` 桶 | ✅ 可删(purge 清平台副本) |
| **`hosted`** | 平台只存 **DB 指针**,字节留在源端 | 三方 S3 / 外部对象(不动) | ❌ 403 拒删(删源红线,只能 `unhost` 摘引用) |

**删除门**(`backend/app/api/v1/datasets.py:1147` / `:1052-1059`):某数据集含**任意** `origin="hosted"` 版本 → `delete` / `batch-delete` 直接 403;`_purge_dataset`(`:1062`)注释明确"绝不调用任何 S3 删除"。这条线是 §6.① 的伏笔。

> 版本不变量(`backend/app/models/dataset_version.py:13-18`):版本一经写入不再修改;"编辑"数据集 = 跑 Job 产新版本。血缘由 `DatasetVersion.produced_by_job_id`(版本由谁产出)+ `JobInput`(Job 吃了哪些版本作输入)两张表构成有向图。

## 1. 三层管道(统一契约)

所有 managed 接入路径最终都汇过同一条管道:

```
┌─ L1 连接器协议 (connectors/base.py:39) ──────────────────────────┐
│  probe(config) → (bool, ms, msg)     连通性探测                   │
│  list_tables(config) → list          列表/列对象/列目录           │
│  run_ingest(session, task, ds, *, job_id) → [(Dataset, Version)]  │
│  异常二分:IngestError(配置/连接失败) vs ConnectorNotReady(驱动未装,诚实降级) │
└───────────────────────────────────────────────────────────────────┘
                              ▲
┌─ L2 注册表分发 (connectors/__init__.py:30) ───────────────────────┐
│  REGISTRY: (type, db_kind) → 无状态单例 connector                 │
│  resolve(type_, db_kind) —— 单一查表入口,三处分发点共用           │
└───────────────────────────────────────────────────────────────────┘
                              ▲
┌─ L3 落地枢纽 (landing.py) ────────────────────────────────────────┐
│  normalize_to_records(bytes, fmt) → list[dict]   异构 → 规范记录  │
│  land_records(records, ...) → (Dataset, v1 版本)  managed 主出口  │
│  land_upload / land_upload_raw                   本地上传薄封装  │
└───────────────────────────────────────────────────────────────────┘
```

- **L1 连接器协议**(`base.py:39-63`):`@runtime_checkable` Protocol。`StructuralStub`(`base.py:66-98`)是"结构就绪但无驱动"的复用基类(达梦/巨杉/Hive/Doris 用)。共享工具 `_build_queries(extract)`(`base.py:107`,把 `task.extract` 翻成 `[(suffix, sql)]`)、`apply_filter_operators`(`base.py:128`,可选 data-juicer 算子过滤)。
- **L2 注册表**(`connectors/__init__.py:30-54`):`(type, db_kind)` 键控。s3/hdfs/api 不看 `db_kind`;database 按品牌(postgresql/hologres/kingbase/gaussdb → `PgConnector`,goldendb → `MysqlConnector`,dameng/sequoiadb/hive/doris → 各 proprietary connector)。
- **L3 落地枢纽**(`landing.py`):`land_records`(`:227`)是 managed 落地的**唯一主出口**,负责写 jsonl + 建 Dataset + 建 v1 版本。**注意:有两条路径(API 推送、upload-media/batch)绕过它自己落地**,见 §3。

## 2. 归一化:异构数据 → 三种产物格式

`normalize_to_records`(`landing.py:173`)把任意源文件字节压成 `list[dict]`,再据内容决定落地成哪一态:

| 版本 `format` | 触发条件 | 落地方式 |
|---|---|---|
| **`jsonl`** | 文本/表格/文档(jsonl/json/csv/tsv/txt/xlsx/xls + pdf/doc/docx/ppt/pptx/html 走 MarkItDown) | `normalize_to_records` → 逐行写 `data.jsonl` |
| **`manifest`** | 媒体集(图/音/视频批量) | 每文件拷进平台 MinIO + 一行 jsonl 引用(`images`/`audios`/`videos` 字段 + dj 特殊 token + `__member` 块) |
| **`<原扩展名>`** | 单个二进制 | `land_upload_raw` 原样存字节,`rows=None`,不解析 |

> **关键区分**(三轴设计稿 §5 反复强调):`source_format`(用户视角**原始**格式,如 `docx`)≠ `DatasetVersion.format`(归一后**存储**格式,如 `jsonl`)。前者给用户看,后者是平台内部产物。数据库直连无文件载体 → `source_format=null`。

## 3. 四条接入路径

### 3.1 本地上传(`/datasets/upload*`,3 个端点)

```
客户端 ──multipart──▶ datasets.py
                         │
        ┌────────────────┼─────────────────────┐
        ▼                 ▼                     ▼
   POST /upload        POST /upload-media   POST /upload-batch
   (单文件)            (批量媒体)           (批量同格式文本)
        │                 │                     │
   ┌────┴─────┐      不解析,逐文件        逐文件 normalize
   文本    二进制      upload_object        合并 + 原件留 MinIO
   │         │       → manifest jsonl          │
 land_     land_          │                     │
 records   upload_raw     │              records_to_jsonl_bytes
 │         │              │              → upload_jsonl_to_uploads
 └────┬────┘              │                     │
      ▼                   ▼                     ▼
   Dataset + Version   Dataset + Version   Dataset + Version
   source_kind=         format=manifest     format=jsonl
   local_upload         origin=managed      origin=managed
   文本→本地磁盘        →平台 MinIO         →平台 MinIO
```

| 端点 | 行号 | 归一化 | 物理落点 | 产物 format |
|---|---|---|---|---|
| `/upload` | `datasets.py:119` | 文本→`land_upload`→jsonl;二进制→`land_upload_raw` | 本地 `datasets_dir` | `jsonl` / `<ext>` |
| `/upload-media` | `datasets.py:276` | 不解析,拷 MinIO + manifest(限单模态) | 平台 MinIO | `manifest` |
| `/upload-batch` | `datasets.py:426` | 各自 normalize 合并 + 原件留 MinIO | 平台 MinIO(原件 + 合并 jsonl) | `jsonl` |

三端点统一 `source_kind="local_upload"`、`source_format=<ext>`、`origin="managed"`。`upload-batch` 注释(`datasets.py:445`)**特意强调** `origin='managed'`(非 hosted)"平台自有、可正常删除"——这是 §6.① 的对照点。

### 3.2 数据库采集(⚠️ 同一任务,**两条分叉**,行为差异巨大)

一个 `IngestTask` 走哪个端点,决定它进入完全不同的两条管道:

| | `POST /ingest-tasks/{id}/generate-dataset`(`ingest_tasks.py:407`) | `POST /ingest-tasks/{id}/rerun`(`ingest_tasks.py:305`) |
|---|---|---|
| 建 Job | ❌ 不建(`produced_by_job_id=None`,**无血缘**) | ✅ 建 `Job(type=ingest)` |
| 调 `land_records`? | ❌ 否,自己写 | ✅ 是,经 connector.run_ingest |
| 存储 | **平台 MinIO** `s3://…/v<n>/data.jsonl` | **本地 `datasets_dir`** |
| 版本语义 | **同数据集追加版本**(v1/v2/…,首次绑定 `task.dataset_id`) | 每查询新建数据集(恒 v1) |
| **`origin`** | **`"hosted"`** ⚠️ 见 §6.① | `"managed"` |
| 品牌门 | **仅 PG 系 + GoldenDB**(`_CSV_DATASET_KINDS`,`ingest_tasks.py:433`) | 全部已注册品牌(国产库多数 `ConnectorNotReady`) |
| dispatch | goldendb→`mysql.fetch_records`,其余→`pg.fetch_records`(`:61-68`) | `resolve(type, db_kind).run_ingest` |

```
ingest_task
   │
   ├──/generate-dataset──▶ _fetch_db_records(内存拉行)
   │                          │
   │                     records_to_jsonl_bytes
   │                          │
   │                     upload_jsonl_to_uploads  ──▶ 平台 MinIO s3://
   │                          │
   │                     建/绑 Dataset + 追加版本
   │                     origin=hosted ⚠️, source_datasource_id=None
   │
   └──/rerun──▶ resolve(type,db_kind).run_ingest(session,task,ds,job_id=job.id)
                   │
              pg/mysql: _build_queries → conn.fetch → apply_filter_operators
                   │
              land_records(source_kind=database, source_format=None,
                           produced_by_job_id=job.id, origin=managed)
                   │
              本地 datasets_dir/<id>/v1/data.jsonl
```

**版本追加绑定**:`IngestTask.dataset_id`(`models/ingest_task.py:38`,无 FK 弱引用,迁移 `0015`)。`generate-dataset` 首次运行建 Dataset 并写回 `task.dataset_id`;后续运行 `version_no = MAX+1`,版本写各自 MinIO 文件夹(`<id>/v<n>/`)。`UNIQUE(dataset_id, version_no)` 保证不撞(`dataset_version.py:22`)。

### 3.3 API 推送(`/ingest/push/{token}`)—— 唯一"追加版本"的入站路径

**绕过 `land_records`**,自己落地(`connectors/push.py:91`),因为需要 `land_records` 不支持的"同数据集追加版本"语义:

```
外部系统 ──POST /ingest/push/{token}──▶ ingest_push.py:124
            body: {records:[...], semanticType?, idempotencyKey?}
              │
              ├─ 限流(内存令牌桶 60/60s) ──▶ 超 429
              ├─ token→DataSource(type=api, config.pushToken) ──▶ miss 401
              ├─ 解析 body(json/array/jsonl) ──▶ 坏 400
              │
              ▼
        push.land_push_records
              │
              ├─ 幂等预检(内存缓存 10min TTL) ──▶ 命中直接返回首版
              ├─ 语义归一(apply_semantic_spec,非严格)
              │
              ├─ datasource.config.boundDatasetId 命中?
              │     ├─ 否(首次):建 Dataset + 回写 boundDatasetId, v1
              │     └─ 是(后续):取已绑 Dataset, version_no=MAX+1
              │
              ├─ 写 datasets_dir/<id>/v<N>/data.jsonl
              ▼
        DatasetVersion(format=jsonl, origin=managed,
                       source_kind=api_push, source_format=jsonl)
```

- **绑定**:`datasource.config["boundDatasetId"]`(JSONB,首次推送写入)。一个 `DataSource(type=api)` → 一个 `Dataset` → N 个版本,每次推送产一个全量快照版本(非跨版本行追加)。
- **限流 / 幂等均为单进程内存**(`ingest_push.py:50` / `push.py:53`):多 worker 部署失效,代码注释已承认,生产需换 DB 去重(已知技债)。
- **token 轮换**:`POST /datasources/{id}/rotate-push-token`(admin,`ingest_push.py:207`),`secrets.token_urlsafe(16)`,旧 token 即时失效。

### 3.4 托管 / 零拷贝(`/datasets/host-s3`、`/host-platform`)—— 不下载一个字节

```
三方 S3 对象                datasets.py
  s3://bucket/key   ──host-s3──▶ 逐 key stat_object(只取 size)
                                   │
                              建 Dataset + Version
                              storage_uri=s3://bucket/key
                              origin=hosted, rows=null
                              source_datasource_id=ds.id   ← 凭证回源

平台 MinIO 对象             datasets.py
  s3://bucket/key   ──host-platform──▶ 逐 key stat_object
                                   │
                              建 Dataset + Version
                              storage_uri=s3://bucket/key
                              origin=hosted, rows=null
                              source_datasource_id=None     ← 凭证走 platform_config
```

| 端点 | 行号 | 凭证来源 | `source_datasource_id` |
|---|---|---|---|
| `/host-s3` | `datasets.py:1355` | 外部 `DataSource(type=s3)` | `ds.id`(回源找 S3 凭证) |
| `/host-platform` | `datasets.py:1450` | `platform_config()`(平台 MinIO) | `None`(回退平台配置) |

字节永远留在源端,平台只存 DB 指针 → `rows=null`、删不掉、`unhost`(`:1551`)只摘平台引用不动 S3。预览/物化按 `storage_uri` 的 `s3://` scheme 走 MinIO(`datasets.py:446` 注释:"不再凭 origin 二分")。

## 4. 三轴赋值总矩阵(核验汇总)

> `source_kind` / `source_format` 在 `Dataset` 上(三轴之二,`models/dataset.py:34-37`);`semantic_type` 在 `Dataset` + `DatasetVersion` 双写(`:30` / `dataset_version.py:45`);`origin` / `format` 在 `DatasetVersion` 上。

| 接入路径 | `source_kind` | `source_format` | `semantic_type` | 版本 `format` | 版本 `origin` | 物理落点 | `rows` |
|---|---|---|---|---|---|---|---|
| `/upload`(文本) | `local_upload` | `<ext>` | 显式或推断 | `jsonl` | `managed` | 本地磁盘 | 行数 |
| `/upload`(二进制) | `local_upload` | `<ext>` | 显式或推断 | `<ext>` | `managed` | 本地磁盘 | `None` |
| `/upload-media` | `local_upload`¹ | `<ext>` | 显式或推断 | `manifest` | `managed` | 平台 MinIO | 文件数 |
| `/upload-batch` | `local_upload`¹ | `<ext>` | 显式或推断 | `jsonl` | `managed` | 平台 MinIO | 合并行数 |
| DB `/generate-dataset` | `database`² | `null` | `structured` | `jsonl` | **`hosted`** ⚠️ | 平台 MinIO | 行数 |
| DB `/rerun`(pg/goldendb) | `database` | `null` | `structured` | `jsonl` | `managed` | 本地磁盘 | 行数 |
| S3 采集(文本) | `object_store` | `<ext>` | 显式或推断 | `jsonl` | `managed` | 本地磁盘 | 行数 |
| S3 采集(媒体) | `object_store`¹ | `<ext>` | 显式或推断 | `manifest` | `managed` | 平台 MinIO | 文件数 |
| HDFS 采集 | `hdfs` | `<ext>` | 显式或推断 | `jsonl` | `managed` | 本地磁盘 | 行数 |

| `/host-s3` | `null`³ | `null` | 显式或推断 | `<ext>` | `hosted` | 外部 S3(指针) | `None` |

## 5. 存储双轨 + 版本号语义

```
managed 副本落在两处之一:
  ├─ 本地磁盘   settings.datasets_dir/<dataset_id>/v<N>/data.jsonl   (jsonl)
  │                                                   /<filename>     (二进制原样)
  └─ 平台 MinIO  uploads 桶  s3://<bucket>/<dataset_id>/v<N>/data.jsonl
                              s3://<bucket>/<dataset_id>/manifest.jsonl  (媒体集)

hosted:只在 DB,storage_uri 指向源端 s3://,字节不动,rows=null
```

**版本号**:`UNIQUE(dataset_id, version_no)`,同数据集内自增 1,2,3…。两种语义:
- **追加版本**(同数据集越积越多):DB `generate-dataset`、API 推送 —— 靠 `ingest_tasks.dataset_id` / `datasource.config.boundDatasetId` 绑定。
- **每次新建数据集 + v1**:其余所有路径。

版本展示标签 `v{YYYY.M.D} (#{version_no})`。

## 6. 已知问题(fail-loud,均已源码核验)

> 本节是接入体系当前**真实存在**的冲突,不是设计意图。按 Rule 12 显式记录,改动时须先处理。

### ① DB `/generate-dataset` 的 `origin="hosted"` 标记 → 采集来的数据集**无法删除**(最严重)

证据链(已逐行核验):

- `ingest_tasks.py:514` —— DB 采集版本写 `origin="hosted"`
- `datasets.py:1052-1059` —— `_has_hosted_version` 查 `origin == "hosted"`
- `datasets.py:1147` —— `delete_dataset` 命中 hosted → **403**

**可观测结果**:任何用 `generate-dataset` 从 PG/GoldenDB 采集来的数据集,**删除/批量删除永远 403**,只能走 `unhost`——但 `unhost` 是为三方 S3 设计的(DB 采集数据不在三方 S3)。而该路径的数据明明是平台自己物化到 MinIO 的副本(`source_datasource_id=None`,可删)。

**自相矛盾的注释**:`datasets.py:445-447` `upload-batch` 端点明确写"`origin='managed'`(非 'hosted'):平台自有、可正常删除;预览\物化按 `storage_uri` 的 s3 scheme 走平台 MinIO,**不再凭 origin 二分**"。说明作者已知此坑——但:
- **预览/物化**:已改成看 `storage_uri` scheme ✅
- **删除门**:仍在用老的 `origin` 二分 ❌

→ `origin` 字段语义在代码里已**分裂**。**建议(最小改动)**:把 `generate-dataset` 的版本 `origin` 改回 `"managed"`(它本质是平台 MinIO 受管副本);或让删除门也改成看可删性而非 `origin`。

### ② proprietary 连接器 `run_ingest` 调 `land_records` **签名不匹配**(潜伏 TypeError)

`proprietary.py`(达梦/巨杉/Hive/Doris)的 `run_ingest` 用 `land_records(name=…, source_uri=…, job_id=…)` 调用,但 `land_records` 实际签名是 `dataset_name=…/source_kind=…/source_format=…/produced_by_job_id=…`(`landing.py:227`)。**驱动一旦装上就 `TypeError`**。目前因驱动缺失只抛 `ConnectorNotReady`,是潜伏 bug——国产库启用(参见达梦等接入)时会暴雷。

### ③ 其它小项

- `landing.py:1-6` 文件头注释"当前实现首个连接器——本地上传"**已过时**(实际已有 pg/mysql/hdfs/objectstore/push 五条路径)。
- `_new_dataset_id` / `_new_version_id` 在 `landing.py`、`push.py`、`datasets.py` **重复定义三份**(格式相同,可收口)。
- API 推送的限流 + 幂等、cron 调度,均为**单进程内存/单实例假设**(代码注释已声明,生产部署需替换)。
- 前端 `presets` 页仍用老 `dataType` 枚举筛选,未跟上三轴(见类型三轴设计稿 §8 改动面未含 presets)。
