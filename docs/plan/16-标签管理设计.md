# 16. 标签管理设计

> 状态:已批准(2026-06-25)　·　关联:`09-分类管理设计.md`、`15-数据集接入原理.md`、迁移 `0018_dataset_tags`

## 1. 背景与现状

平台已有两套数据集元数据:

- **分类(Category)**:受控分类库,树形(`parent_id` 邻接表),数据集/数据源/采集任务各**单选**挂一个。
  已有完整 CRUD(`/api/v1/categories`)+ 管理页(`/ingest/categories`)。
- **标签(Tag)**:`tags` + `dataset_tags` 两表(迁移 `0018` 已建),**多对多**挂在数据集上,
  自由输入(find-or-create)。但**没有管理页 / 管理类 API**——标签仅在编辑数据集时被隐式创建,
  无法全局列出 / 重命名 / 删除 / 看使用情况。

## 2. 目标

1. **新增「标签管理」**:为现有标签池提供管理 UI + API(列出含使用数、新建、重命名、删除、批量删除、合并)。
2. **菜单合并**:把「分类管理」从 **数据接入** 移到 **数据集仓库**,与「标签管理」并列同父。

## 3. 方案设计

### 3.1 菜单重构(routes + i18n)

```
数据集仓库(datasets)
├─ 数据集列表
├─ 已发布数据集
├─ 分类管理   (从 /ingest/categories 迁到 /datasets/categories)
└─ 标签管理   (新增 → /datasets/tags)
```

- `frontend/config/routes.ts`:把 categories 路由从 `/ingest` 子树迁到 `/datasets` 子树;新增
  `{ path: '/datasets/tags', name: 'tags', component: './datasets/tags' }`。
- 旧路径 `/ingest/categories` 保留一行 `redirect → /datasets/categories`(书签兼容)。
- `frontend/src/locales/zh-CN/menu.ts`:`menu.ingest.categories` → `menu.datasets.categories`;
  新增 `menu.datasets.tags: '标签管理'`。

### 3.2 后端 —— 新增 `/api/v1/tags` 路由(对齐 `categories.py`)

**无需 DB 迁移**(`tags` / `dataset_tags` 表已存在)。复用 `datasets.py` 现有
`_sync_dataset_tags` / `_dataset_tags_map` 辅助函数。

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/v1/tags` | 列表 `[{id, name, usageCount, createdAt}]`(usageCount = 用此标签的数据集数) | 全员 |
| POST | `/api/v1/tags` | 新建 `{name}`,find-or-create(同名直接返回已存在项) | admin |
| PATCH | `/api/v1/tags/{id}` | 重命名 `{name}` | admin |
| DELETE | `/api/v1/tags/{id}` | 删除 + **级联**(解绑所有 `dataset_tags`) | admin |
| DELETE | `/api/v1/tags` | 批量删除 `{ids[]}` + 级联 | admin |
| POST | `/api/v1/tags/merge` | 合并 `{sourceId→targetId}`:重指 + 删源 | admin |

**关键语义**:

- **重命名**:按 `id` 改 `tags.name`。数据集经 `dataset_tags.tag_id`(id 引用)关联,自动跟随。
  > 注:find-or-create 机制下,旧名日后可能因用户再次输入而被重新创建——属自由标签的正常语义,不拦截。
- **级联删除**(单删 / 批删):
  `DELETE FROM dataset_tags WHERE tag_id=:id` → `DELETE FROM tags WHERE id=:id`。静默解绑。
- **合并**(唯一非平凡操作,需处理「同时含两标签的数据集」去重,复合 PK `(dataset_id,tag_id)` 天然兜底):
  1. `INSERT INTO dataset_tags(dataset_id, tag_id) SELECT dataset_id, :target FROM dataset_tags WHERE tag_id = :source ON CONFLICT DO NOTHING`
  2. `DELETE FROM dataset_tags WHERE tag_id = :source`
  3. `DELETE FROM tags WHERE id = :source`
- **usageCount**:左连接 `COUNT(DISTINCT dataset_tags.dataset_id)`;支持按 name 模糊搜索、按使用数排序。

### 3.3 前端 —— `./datasets/tags/index.tsx`(对齐 `ingest/categories/index.tsx`)

ProTable 列:`名称 / 使用数据集数 / 创建时间`;行操作:`重命名 / 删除`;
工具栏:`新建 / 批量删除 / 合并`(合并弹 Modal 选目标标签,源≠目标)。
颜色沿用现状——前端按 `tag.name` deterministic 哈希到预设色板(不落库)。

## 4. 数据模型变更

**无**。`tags`、`dataset_tags` 表结构不动;仅新增 API + 前端页。

## 5. 测试

后端单测(对齐 categories 测试,新增 `tests/unit/test_tags.py`):
- 新建(find-or-create 幂等)、重命名(按 id 全局生效)、列表 usageCount 正确;
- **删除级联**:删 tag 后 `dataset_tags` 中对应行消失、数据集仍在;
- **批量删除**级联;
- **合并**:源标签数据集全部重指到目标;**重点**——同时含 source+target 的数据集不重复(复合 PK 去重)、合并后源标签删除;
- 权限:非 admin 写操作 403。

## 6. 范围外(YAGNI,显式声明)

- 标签**保持扁平**(不加层级——层级是分类的职责)。
- 标签**仅挂数据集**(不扩到数据源 / 采集任务;跨实体标签属未来工作)。
- 不做颜色管理(沿用 name 哈希自动配色)。
- 不做标签分组 / 同义词词典。

## 7. 验收

- 数据集仓库菜单下并列「分类管理」「标签管理」;旧 `/ingest/categories` 跳转至新路径。
- 标签管理页:能列出标签 + 各自被多少数据集使用;新建 / 重命名 / 删除 / 批量删除 / 合并均生效。
- 删除某标签后,使用它的数据集仍存在、仅标签消失;合并后源标签消失、目标标签使用数正确。
