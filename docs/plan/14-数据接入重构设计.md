## 0. 背景与现状结论

数据接入原始需求三行,按「支持项完整性」评分,共 **5 + 8 + 11 = 24** 项:

- **接入方式 5 项**:① S3(OSS/OBS)+ HDFS 拉取;② 手动上传本地文件;③ 直连 8 个国产/大数据库(达梦/GoldenDB/人大金仓 kingbase/华为 gaussdb/阿里 hologres/巨杉 sequoiadb/hive/doris);④ 外部服务 API 推送(承诺支持即可);⑤ 配置采集任务批量拉取。
- **数据类型 8 项**:① 多模态(语音/图片/视频/文本)+跨模态;② 结构化与非结构化;③ COT 思维链;④ QA 问答对;⑤ 偏好 preference;⑥ 时序 timeseries;⑦ GIS 位置;⑧ 不同类型融合,对外统一语义。
- **数据格式 11 种**:TXT/pdf/ppt/doc/docx/xlsx/xls/csv/tsv/html/jsonl。

## 1. 架构:四层 + 一个注册表 + 一个新维度

需求本质是**格式 ↔ 语义类型正交**,中间靠「规范化记录 `list[dict]`」连接。落地为四层,每层一个明确插入点。**关键:语义类型走新列 `semantic_type`,绝不动现有 `data_type` 功能键。**

```
┌─ L1 来源连接器(Connector)──────── 协议族复用 · dict 注册表分发
│        │ → bytes / list[dict] 原始记录
│  L2 格式解析(已存在,不动)───────── landing.normalize_to_records,11/11 真解析
│        │ → list[dict] 规范记录
│  L3 语义类型 + 字段映射(SemanticSpec)── 按 semantic_type 校验必填字段 + 归一别名
│        │ → list[dict] 已校验记录
└─ L4 统一语义快照(Snapshot)──────── land_records 写 DatasetVersion.semantic_type 版本快照
         │ →(默认)不污染逐行 jsonl;下游零感知
   下游(engine/quality/review/export)── 读 jsonl,行内容不变,旧消费者零改动
```

| 层 | 职责 | 现状落点 | 重构后落点 |
|----|------|----------|------------|
| **L1 来源连接器** | 任意来源 → 字节/记录 | `datasources.py` if/elif + `ingest_runner.run_pg_ingest` | 新 `connectors/` 包,注册表按 `(type, db_kind)` 派发 |
| **L2 格式解析** | 字节 → `list[dict]`(11 格式) | `normalize_to_records`(已满足) | **零改动保留**,被 L1 复用 |
| **L3 语义类型 + 字段映射** | 10 语义枚举 + 每类型必填 schema 校验/别名归一 | 无 | 新 `semantic_registry.py` + `apply_semantic_spec` |
| **L4 统一语义快照** | 跨类型统一表达 + 可筛选 | 无 | `land_records` 写 `DatasetVersion.semantic_type`(版本级,**默认不写逐行 `__adp`**) |

**唯一写出口收口**:所有连接器最终都汇到 `landing.land_records`(现状已如此),L3/L4 只改这一个函数 → 下游零改动。

### 1.1 为什么必须新增 `semantic_type` 而非复用 `data_type`(对抗评审核心修订)

v1 计划把 `data_type` 收紧为 10 类枚举。**经核验这会造成三处确定性回归 + 一处测试破坏**:

1. **upload-media 媒体接入断裂**:`_MEDIA_FIELD.get(data_type)`(`datasets.py:245,503`)依赖 `data_type ∈ {image,audio,video}`;一旦合并进 `multimodal`,`.get("multimodal")→None` → 媒体接入 400、丢失 manifest 字段映射。
2. **数据接入页分栏失效**:前端按 `dataType=<ACCESS_TYPES.key>`(sql/image/csv-tsv/...)拉列表,后端按 `data_type==` 过滤;收紧/改写会让历史数据集从对应分栏消失。
3. **DatasetUpdate 422**:存量 `data_type ∈ {sql,image,audio,video,csv-tsv,log,json}`;若 `DatasetUpdate.data_type` 收紧为枚举,编辑任意字段时前端回填旧值会被 Pydantic 整单 422 拒绝。
4. **采集落地点测试破坏**:`run_pg_ingest` 现写 `data_type="sql"`(`ingest_runner.py:110`,注释明言归到 SQL 接入栏),`test_ingest_tasks.py:314` 断言 `ds_row.data_type=="sql"`。改写即破坏断言 + 前端 SQL 分栏过滤。

**结论(Rule 7,选更稳的现状契约,不混血)**:`data_type` = **接入/格式功能键**(原样保留,free-string,不收紧、不改写);`semantic_type` = **10 类 LLM 语义维度**(新增、nullable、枚举校验)。两者正交:一个 `data_type=image` 的数据集其 `semantic_type=multimodal`;一个 `data_type=sql` 的数据集其 `semantic_type=structured`。**所有原 v1 的四处回归在此架构下消失。**

## 3. 语义类型层(SemanticType 注册表)

### 3.1 SemanticType 枚举(10 类,覆盖数据类型 8 项)

**新建 `backend/app/services/semantic_registry.py`**
```python
from enum import StrEnum

class SemanticType(StrEnum):
    TEXT = "text"               # 文本(非结构化文本的统一落点)
    STRUCTURED = "structured"   # 需求#2:结构化(表格/库表/csv)
    UNSTRUCTURED = "unstructured"  # 需求#2:非结构化(文档/日志的"文本可解析"侧)
    MULTIMODAL = "multimodal"   # 需求#1:多模态 + 跨模态
    COT = "cot"                 # 需求#3:思维链
    QA = "qa"                   # 需求#4:问答对
    PREFERENCE = "preference"   # 需求#5:偏好
    TIMESERIES = "timeseries"   # 需求#6:时序
    GIS = "gis"                 # 需求#7:位置
    FUSION = "fusion"           # 需求#8:融合 / 统一语义
```

> 与现有 `data_type` 关系:`data_type` 仍是接入键(sql/image/...),`semantic_type` 是语义维度。read 层提供 `infer_semantic_from_data_type(data_type)` 便捷映射(sql→structured、image/audio/video→multimodal、csv-tsv→structured、pdf/doc/...→unstructured、log/txt/json→text),供前端默认展示与采集落地点填充,**不写回 `data_type`**。

### 3.2 每类型标准 Schema(必填字段 + 字段映射别名 + 校验)

`SEMANTIC_SCHEMAS: dict[SemanticType, SemanticSpec]`,每项含 `required`(必填标准名)、`aliases`(别名→标准名)、`media_fields`(多模态用)、`validate`(逐行校验):

| semantic_type | 必填字段(标准名) | 字段映射 alias(来源 → 标准名) | 校验规则 |
|-----------|------------------|-------------------------------|---------|
| `text` | `text` | `content`/`body`/`line`→`text` | 至少一个非空 `text` |
| `structured` | (任意非空列,行须 dict) | — | 每行 ≥1 列;column union 收集进 `SemanticReport`(不写库,本期仅回报告) |
| `unstructured` | `text` | `markdown`/`paragraph`→`text` | 同 text。**注意**:本类型只覆盖「非结构化数据中可解析为文本」的一半;二进制原样存(`land_upload_raw`)那一半见 §3.6,**不经本层** |
| `multimodal` | `modalities`(≥1) | `image(s)`→`images`,`audio(s)`→`audios`,`video(s)`→`videos`,`caption`/`text`→`text` | ≥1 媒体字段非空;**跨模态**=同行出现 ≥2 个媒体/文本字段时 `modalities` 列全部 |
| `cot` | `question`,`reasoning`,`answer` | `input`/`prompt`→`question`,`chain_of_thought`/`rationale`/`thought`/`cot`→`reasoning`,`output`/`response`→`answer` | 三者皆非空 |
| `qa` | `question`,`answer` | `q`/`prompt`/`instruction`→`question`,`a`/`response`/`output`→`answer` | 两者皆非空 |
| `preference` | `prompt`,`chosen`,`rejected` | `question`/`input`→`prompt`,`accepted`/`win`→`chosen`,`loser`/`lose`/`reject`→`rejected` | 三者皆非空 |
| `timeseries` | `timestamp`,`value` | `time`/`ts`/`date`→`timestamp`,`val`/`metric`→`value` | `timestamp` 可解析为时间;`value` 数值 |
| `gis` | `lat`,`lon` | `latitude`/`y`→`lat`,`longitude`/`lng`/`x`→`lon` | lat∈[-90,90],lon∈[-180,180];可选 WKT/GeoJSON 透传进报告 |
| `fusion` | — | — | 不强校验;融合的上游版本 id 列表记入 `DatasetVersion` 的 `note`/独立字段(见 §5) |

### 3.3 校验/映射方案(纯函数,纯单测)

`apply_semantic_spec(records: list[dict], semantic_type: str | None, *, strict: bool = False) -> tuple[list[dict], SemanticReport]`:
1. `semantic_type` 为 None 或不在枚举 → **不校验**(向后兼容),`SemanticReport.validated=False`,记录原样返回。
2. 命中枚举 → 逐行 alias 归一(**只 rename 不丢原字段**)→ 校验必填 → 收集 `column_union` / `bad_rows`。
3. 失败策略(Rule 12):
   - **非严格(默认,采集/推送批量)**:`bad_rows` 计数进 `SemanticReport`,**不阻断落地**,报告随响应回传;
   - **严格(上传单文件,query `strict=true`)**:`bad_rows>0` 抛 `SemanticValidationError` → 422。

**关键:不破坏 11/11 格式解析** —— `apply_semantic_spec` 在 `normalize_to_records` **之后**调用,输入已是 `list[dict]`,与格式无关。

### 3.4 旧值映射(read 层便捷展示,不写库)

read 层提供 `infer_semantic_from_data_type`(§3.1 映射表)。当数据集 `semantic_type IS NULL` 但有历史 `data_type` 时,read 模型可计算性回填一个**展示用** semantic(不落库)。**`data_type` 本身一字不改、不收紧、不回填** → 无 DatasetUpdate 422、无分栏失效。

### 3.5 语义类型自动推断(复用既有 AI 端点)

`semantic_registry.infer_semantic(sample_records) -> SemanticType`:按字段命中推断(有 chosen/rejected→preference;有 reasoning→cot;有 question+answer→qa;有 lat/lon→gis;有 timestamp→timeseries;否则 structured/text)。上传/推送时若未显式给 `semantic_type`,后端调此函数填 `DatasetVersion.semantic_type`(纯函数,可单测)。前端接入助手已有 `POST /api/v1/ai/infer-schema`,展示层可复用(本期不接管 AI 推断字段,Rule 2)。

### 3.6 非结构化二进制(评审点:land_upload_raw 不经类型层)

- **诚实定位**:非结构化「二进制媒体/原档」侧 = **结构就绪**(有 `semantic_type` 标注与多模态 manifest 路径,但不经字段校验层);非结构化「可解析文本」侧(pdf/doc/html→`normalize`→`unstructured`)= **可实现且可测**。覆盖矩阵据此分列(见 §11),**不把二进制侧并入 unstructured 文本算 fully**。

### 4.2 连接器协议(`base.py`,函数式 Protocol,非 ABC 继承)

与现有 `run_pg_ingest(session, task, ds, *, job_id)` 签名零冲突:
```python
class Connector(Protocol):
    async def probe(self, config: dict) -> tuple[bool, int, str]: ...        # 测连接
    async def list_tables(self, config: dict) -> list[str | dict]: ...       # 列表/列对象
    async def run_ingest(self, session, task, datasource, *, job_id) \
        -> list[tuple[Dataset, DatasetVersion]]: ...                         # 真拉取
```
`base.py` 提供 `STRUCTURAL_STUB`:probe 返回 `(False, 0, "<品牌> 连接器结构就绪,本环境未装驱动 <pkg>,暂不可真连")`,list/run 抛 `ConnectorNotReady`。**诚实失败,绝不伪造 success**(纠正现状 `randint` 假成功,Rule 12)。

## 11. 需求逐项覆盖矩阵

> 状态定义:`fully`=可实现且本地可测;`structural`=结构就绪(代码骨架完整,本地无环境验证);`promised`=承诺级(题目允许只承诺);`missing`=未覆盖。

| 需求项 | 状态 | 怎么覆盖 |
|--------|------|----------|
| 接入①-S3/OSS/OBS 拉取 | **fully** | objectstore.S3Connector.run_ingest 走 extract.path/glob→download_to_temp→normalize→apply_semantic_spec→land_records,补齐 rerun 缺口;OSS/OBS 同 connector。本地 MinIO 集成测 |
| 接入①-HDFS 拉取 | **structural** | WebHDFS REST;`_build_webhdfs_url`/`_parse_liststatus` 纯单测;端到端需 HDFS 集群(承诺级) |

| 接入③-postgresql | **fully** | run_pg_ingest 真连真拉,搬入 PgConnector,自引用 PG 集成测 |

| 接入③-gaussdb | **promised** | 同上,真品牌需华为 gaussdb 环境 |

| 类型②-结构化 | **fully** | SemanticType.structured;采集/csv 落 structured;纯单测 |
| 类型②-非结构化(文本侧) | **fully** | unstructured(text 必填);pdf/doc/html→normalize→unstructured;纯单测 |
| 类型②-非结构化(二进制侧) | **structural** | 评审点:land_upload_raw 二进制不经字段校验,仅写版本级 semantic_type 标注 |
| 类型③-COT | **fully** | cot(question/reasoning/answer + 别名归一);纯单测 |
| 类型④-QA | **fully** | qa(question/answer + 别名);纯单测 |
| 类型⑤-偏好 | **fully** | preference(prompt/chosen/rejected + 别名);纯单测 |
| 类型⑥-时序 | **fully** | timeseries(timestamp/value + 别名 + 校验);纯单测 |

| 类型⑧-融合/统一语义 | **structural** | 评审点:仅 fusion 枚举 + 上游版本 id 占位;统一读接口/融合算子编排为加工层后续,本期不可消费 |
