## 2. 后端

### 2.1 数据模型(新建 migration 0006)
- `users`:id(`usr-`+hex)/ username(unique)/ password_hash / role(`admin`|`user`)/ display_name / disabled(bool)/ created_at。
- `audit_logs`:id / username / action(如 `dataset.delete`)/ method / path / target(可空)/ status_code / created_at(索引)。
- **种子**(migration 内插入):`admin`/`ant.design`→admin、`user`/`ant.design`→user(密码哈希)。**必须保证 `admin/ant.design` 仍可登**(不破坏线上)。

### 2.2 认证(不引新依赖,用 stdlib)
- 密码:`hashlib.pbkdf2_hmac('sha256', pwd, salt, 200_000)`,存 `pbkdf2$<iter>$<salt_hex>$<hash_hex>`;`verify_password` 常量时间比较。
- 令牌:HMAC-SHA256 签名 `"<username>.<exp_ts>.<b64sig>"`,放 httpOnly cookie(沿用名 `adp_session`,samesite=lax)。密钥取 `settings.auth_secret`(env `AUTH_SECRET`,带 dev 默认值)。有效期如 7 天。
- 文件:`app/services/auth.py`(hash/verify/sign/parse)+ 改写 `app/api/compat.py`:
  - `POST /login/account`:查 user→verify_password→签发 cookie;失败 `{status:error,...}` 不设 cookie。
  - `GET /currentUser`:验签 cookie→查 user→返回 `{name, access:<role>, userid, ...}`(沿用现有 payload 形状,`access`=role 供前端 access.ts);无效→401。
  - `POST /login/outLogin`:清 cookie。

### 2.3 鉴权依赖与越权防护
- `app/api/deps.py`:`current_user(adp_session: Cookie)`→User|None;`require_admin`→无 admin 抛 403 `{success:false,message:"无权限"}`。
- **权限矩阵(demo)**:`admin` 全权;`user` 只读浏览 + 可试跑/预览/AI 生成,但**不可**删除/编辑/管理。给以下写端点加 `require_admin`:
  - datasets:`DELETE /datasets/{id}`、`POST /datasets/batch-delete`、`PATCH /datasets/{id}`
  - datasources:`POST/PUT/DELETE /datasources*`
  - (jobs 创建、quality、preview、upload 暂不限,保证核心演示可用;如需更严后续收紧)
- 注:`/api/v1/operators*`、列表/详情/预览等读端点不限。

### 2.4 操作审计
- 中间件 `app/core/audit.py`:对 `/api/v1/**` 的 `POST/PUT/PATCH/DELETE`,响应后写一条 `audit_logs`(username 从 cookie 解析,失败记 `anonymous`;method/path/status_code/target 尽力取路径末段)。读请求不记。
- `GET /api/v1/audit`(`require_admin`):分页 + 可选过滤(username/action/method/时间区间),倒序。

## 3. 前端
- 登录页已对接 `/login/account`,后端换真实鉴权后基本透明(失败提示已在)。
- `src/access.ts`:`canAdmin = currentUser?.access === 'admin'`(currentUser 由 `/currentUser` 返回 access)。
- 用 access 门控:菜单/页面 + 关键按钮——非 admin 隐藏 数据集删除/批量删除/编辑、数据源 新建/编辑/删除 等(`<Access accessible={canAdmin}>` 或按钮 `hidden`)。
- `security` 页(占位→真实):**审计日志列表**(ProTable,admin 可见;username/动作/时间过滤),接 `GET /api/v1/audit`;路由已存在 `/security`。
- api.ts:加 `listAuditLogs(params)`;typings 加 `AuditLog` / 列表参数类型。

## 4. 迁移与不破坏现网
- 新 migration 0006 建表 + 种子;`alembic upgrade head` 在容器入口已自动跑。
- 线上已有 PG(60),升级即建表插种子;**部署后 `admin/ant.design` 必须可登**(种子保证)。
- cookie 名沿用 `adp_session`,旧的明文 role cookie 失效后用户重登即可。

## 5. 风险
- **别把自己锁死**:务必先种子 admin 再加 require_admin;矩阵只限管理类写操作,核心读/演示不受影响。
- 中间件读 body 谨慎(只读 cookie/path/status,不消费 body 流,避免破坏请求)。
- token 密钥 dev 默认值仅开发用;生产应在 deploy/.env 配 `AUTH_SECRET`。
- 前端 access 门控是 UX 层;真正防护在后端 require_admin(双层)。

## 6. 验收
- admin 登录:全功能;user 登录:读浏览 OK,删除/编辑/新建数据源被拦(前端隐藏 + 后端 403)。
- 任一写操作后,security 审计列表出现对应记录(谁/何动作/路径/时间/状态)。
- `admin/ant.design` 线上可登(回归)。
