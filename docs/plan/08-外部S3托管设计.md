# 08 · 外部 S3 数据托管(#18)设计

> 关联:需求 #18(托管三方 S3 数据,可做与受管数据相同操作,**删等数据安全操作除外**)。
> 关联 #1/#3(数据源/接入)。状态:✅ 已实现并部署 10.60.1.60(2026-06-15)。物化策略=**纯引用·按需拉取**。实现见提交 `feat(datasets): #18 外部 S3 数据托管`。
> 测试源:已在 10.60.1.60:9000 部署 MinIO(桶 datasets/uploads,账号 adpadmin)。

## 1. 范围

**做**:把三方 S3(含 MinIO)上的对象**登记为受管数据集版本**(只存引用,不拷贝)。对这些"外部托管"版本支持与受管数据**相同的操作**:浏览/预览/加工/质量评估/内容审核/元数据编辑——**加工与审核产出的是新的受管版本,绝不回写源**。**删除源**及数据安全敏感操作**不提供**;仅 admin 可"取消托管"(移除平台引用,绝不动 S3 源对象)。

**本期不做**:写回 S3、HDFS/其它对象存储托管、跨桶批量同步、S3 事件订阅。

**复用既有模型**:`DatasetVersion.origin` 已含 `hosted`,`storage_uri` 已允许 `s3://...`(模型注释即写明承载 #18)——无需新 origin。

## 2. 后端

### 2.1 依赖与客户端
- **新增依赖**:`minio`(轻量 S3 兼容 SDK,兼容 AWS S3 / MinIO)。写入 `backend/pyproject.toml`;部署镜像 `uv pip install` 自动装。
- `app/services/external_store.py`:
  - `client_for(config) -> Minio`:从 datasource.config(endpoint/accessKey/secretKey,解析 http(s)+host:port、secure 标志)建客户端。
  - `test_connection(config) -> (ok, latency_ms, msg)`:`list_buckets()` 真探活 + 计时。
  - `list_buckets(config) -> [name]` / `list_objects(config, bucket, prefix) -> [{key,size,lastModified}]`(非递归 + 递归可选,带上限如 1000)。
  - `download_to_temp(config, bucket, key) -> Path`:`get_object` 流式写临时文件。
  - `head_records(config, bucket, key, fmt, limit) -> [dict]`:预览用,取前 N 条(jsonl/csv 流式读前 N 行;xlsx/pdf 等二进制则下载后 `normalize_to_records` 取前 N)。

### 2.2 物化解析器(核心)
`app/services/external_store.py` 提供异步上下文管理器:
```
@asynccontextmanager
async def materialized_version(version, session) -> AsyncIterator[Path]:
    if version.origin != "hosted":
        yield Path(version.storage_uri)          # 受管:直接用本地路径
        return
    ds = await session.get(DataSource, version.source_datasource_id)
    raw = download_to_temp(ds.config, *parse_s3_uri(version.storage_uri))  # s3://bucket/key
    jsonl = normalize_to_temp_jsonl(raw, version.format)   # 复用 landing.normalize_to_records
    try: yield jsonl
    finally: cleanup(raw, jsonl)
```
**接入 5 处读点**(把 `Path(version.storage_uri)` 直读改为 `async with materialized_version(v, session) as path:`):
- `app/services/engine.py`:`run_preview`(L110)、`run_process_job`(L161 输入)
- `app/services/quality.py`(L76 input_path)
- `app/services/review_runner.py`(L69 src_path)
- `app/api/v1/datasets.py`:`preview_version`(L272)——hosted 走 `head_records`(避免整对象下载)

加工/审核**产出**仍写受管存储(origin=managed/review),源不动;血缘 JobInput 指向 hosted 输入版本。

- 无其它结构变更(origin/storage_uri/format 复用)。downgrade 删该列。

### 2.4 数据源:真实 S3 接入
- `app/api/v1/datasources.py`:`POST /datasources/test` 与 `create_datasource` 的 **s3 分支**从"配置校验"升级为 `external_store.test_connection` 真探活(connected/failed)。其它类型不变。
- `GET /datasources/{id}/buckets`:列桶(仅 s3,真连)。
- `GET /datasources/{id}/objects?bucket=&prefix=`:列对象。

### 2.5 托管登记 / 取消
- `POST /datasets/host-s3`:body `{datasourceId, bucket, keys:[...], name?, dataType?}`。对每个 key:`stat_object` 取 size/格式 → 建 `Dataset` + `DatasetVersion(origin="hosted", storage_uri="s3://bucket/key", source_datasource_id, format=<由扩展名>, size, rows=null)`,**不下载**。返回创建的数据集。**不加 require_admin**(类比 upload,登记不破坏数据)。
- **删除语义**(#18 排除删源):
  - `DELETE /datasets/{id}` 与 `POST /datasets/batch-delete`:若数据集含 hosted 版本 → 403 `{success:false,message:"外部托管数据不支持删除,请用取消托管"}`(不动 S3,不删本地)。
  - `POST /datasets/{id}/unhost`(`require_admin`):删平台记录(Dataset+hosted版本+血缘边),**绝不调用 S3 删除**;有受管派生版本时也仅删引用。
- 预览端点 `GET /dataset-versions/{id}/preview` 处理 hosted(2.2)。

### 2.6 schema
`app/schemas/dataset.py` 等:`HostS3Request`(datasourceId/bucket/keys/name?/dataType?);DatasetVersionRead 增 `sourceDatasourceId?`;DatasetRead/列表暴露 `hosted: bool`(由是否含 hosted 版本推导,供前端徽标/门控)。

## 4. 操作矩阵(hosted vs managed)

| 操作 | 受管 managed | 外部托管 hosted |
|---|---|---|
| 浏览/详情/预览 | ✓ | ✓(预览按需取前 N) |
| 加工 / 质量 / 审核 | ✓ | ✓(按需拉取→跑;**产受管新版本**,源不动) |
| 元数据编辑(PATCH) | ✓ | ✓ |
| 删除(源/版本) | ✓(admin) | ✗ 禁止(403) |
| 取消托管(移除引用,不动源) | — | ✓(admin) |

## 5. 不破坏现网 / 风险

- 迁移 0008 仅加一可空列;受管数据与既有流程零影响(`materialized_version` 对 managed 直接透传本地路径)。
- **按需拉取代价**:大对象每次加工/质量/审核都整下载到临时区(预览靠流式前 N 缓解)——演示量级可接;大文件成本在 spec 标注,不静默。
- **凭证**:hosted 版本的 S3 凭证取自其 `source_datasource_id` 指向的数据源 config(不另存);数据源删除会使其下 hosted 版本失效(取消托管时一并清理引用)。
- **安全**:删源全程禁止(双层:hosted 删除 API 403 + 前端隐藏);unhost 仅 admin 且只删平台引用。S3 客户端错误(连不上/对象缺失)→ 操作返回明确错误,不 500、不影响受管数据。
- minio SDK 走 datasource 配置的 endpoint;MinIO(60)用 http(secure=false),AWS S3 用 https。

## 6. 验收

- 在 MinIO(60)桶里放一个 jsonl/csv → 平台「托管 S3 数据」登记 → 列表出现带「S3 托管」徽标的数据集,**未发生下载**。
- 预览该版本(从 S3 取前 N);对它跑加工/质量/审核 → 成功且**产出受管新版本**,S3 源对象仍在。
- 删除该 hosted 数据集 → 被拒(403);admin「取消托管」→ 平台引用消失、**S3 源对象仍在**(mc/console 可核)。
- 受管数据集全流程回归不受影响。
