# 13 · 端到端闭环闭合设计

> 状态:**本轮已闭合主干闭环**(导出终端 + 消费门控 + 加工写端点 RBAC + 跨阶段导航)。
> 对照配图 [`12-端到端数据工程流程.svg`](12-端到端数据工程流程.svg)。
> 缘起:经代码级核查,发现按 SVG 描绘的端到端流程**仍未闭环**——数据进得来、出不去。

## 1. 诊断(代码核查,非文档措辞)

端到端目标闭环:`原始数据源 →①接入 →②原始数据湖(草稿版本) →[安全扫描/③质量/④加工/⑤标注] →⑥发布门(scanVerdict须passed) → 算法工程师选已发布训练集`。

主干其实已真实打通(接入→湖→扫描/质量/加工→发布门→算法工程师 presets 只读消费视图存在)。
但有 **3 处真实断点**让它不成闭环:

| # | 断点 | 证据 | 性质 |
|---|------|------|------|
| **1** | 出口取不出数 | 只有逐对象 `member-url`(预览);**managed 本地结构化版本(jsonl/parquet)无对象存储位置 → 没有任何下载出口**,算法工程师拿不出文件 | 闭环终点断开 |
| **2** | 消费无发布门控 | `member-url`(datasets.py)/`files/download-url`(files.py)不校验 `publish_status`,知道 key 即可签出 draft/未发布版本 | 安全不变量破 |
| **3** | 加工写端点零 RBAC | `jobs.py` 写端点(create/rerun/stop/delete/batch-delete)无 `require_admin`,匿名可建/删加工任务(datasets/categories/files 都已门控,此处遗漏) | 跨切面 RBAC 破 |

**非主干阻断**(已确认可旁路,不挡「一个版本走完全程被取走」):⑤数据标注后端+前端全缺(发布门只看 `scan_verdict=passed`,不要求标注完成 → 可旁路)、血缘图可视化(#11)、cron 调度、HDFS/API 采集、manifest 版本不可变、质量同步阻塞。

## 2. 闭合实现

### P1+P2 · 版本级导出端点 + 发布门控(闭环终点)

- 新增 `GET /api/v1/dataset-versions/{id}/download`(datasets.py):
  - 门:`publish_status == published` 才放行,否则 **409**(草稿/已下架不外流)——发布门的消费侧对偶,维持「published ⟹ 可被消费」。
  - managed 本地版本 → `FileResponse` 流式下发(强制下载,文件名带数据集+版本号)。
  - s3 背书版本(hosted 单对象 / manifest 媒体集)→ 302 跳转预签名 GET URL。
- `member-url` 维持**预览**语义(key 归属校验,不门控);导出统一走新端点(消费门控收口于此)。
- 前端:**算法工程师消费视图**(`datasets/presets`)已发布版本表加「下载」动作 → `window.open(/api/v1/dataset-versions/{id}/download)`。

### P3 · 加工写端点 RBAC(跨切面 #5)

- `jobs.py` 的 create / rerun / stop / delete / batch-delete 加 `Depends(require_admin)`,对齐 datasets/categories。匿名→401、非 admin→403。
- **刻意不动**(尊重既有决策,Rule 7/11):`quality`、`content-safety`、`jobs/preview` 维持「分析类不门控」——见 `content_safety.py` 注释「审核属分析类」。若产品要求分析类也门控,另行决策。

### P5 · 跨阶段导航(消除「各页面孤立」的体感)

- `datasets/list` 版本表新增「流程」列:按版本一键进入下一步 **安全扫描 / 质量评估 / 数据加工**(加工 admin 门控),`history.push` 携 `datasetId+versionId`。
- `processing/editor`、`quality/editor`、`content-safety` 三页读 URL query 预选数据集+版本(content-safety 覆盖「默认选最新版」)。**纯加法**:不带 query 时维持原交互。

## 3. 验证

- 新增 `tests/test_dataset_export.py`:门控(draft/unpublished→409)、managed 本地流式下发、s3 跳转预签名、404/410 缺失,共 6 用例。
- `tests/test_job_control.py` 加 `test_job_write_requires_admin`(user→403 / 匿名→401);三个 job 测试 + `test_data_access` 的二进制门控用例补 admin 身份。
- 全量后端 **183 passed**;前端 `tsc` + `biome lint` 清白。

## 3.1 增补(2026-06-28):导出至 S3 + 主数据集页下载入口

> 关联原始需求「支持的操作」第5项:「数据集或者数据支持下载,**导出至本地或者 S3 存储上**」。
> 此前只做了「导出至本地」(download 端点)且入口仅在算法工程师 presets 视图;本次补齐
> 「导出至 S3」并把下载入口接到主数据集详情页。状态:✅ 已实现(后端 + 前端 + 单测)。

> ⚠️ 门控变更(2026-06-28,用户决策):**下载/导出去掉 published 门控**——任意版本(含草稿)
> 均可下载/导出。原 §P1+P2 把下载收口在 published 是为「算法工程师消费训练集」的安全闭环;
> 用户预期是「数据集随手可下载/导出」,故放开。`publish` / `unpublish` 端点本身不受影响,
> `member-url`/`files download-url`(预览)语义也不变。

- **导出至本地(下载)入口扩面**:数据集**详情页**(`datasets/detail`)版本卡对**任意版本**
  新增「下载」按钮 → 复用既有 `GET /dataset-versions/{id}/download`(已去发布门控)。
  对全部可见用户开放(消费动作,非 admin 专属)。
- **导出至 S3(新端点)**:`POST /api/v1/dataset-versions/{id}/export-s3`,body
  `{datasourceId, bucket, prefix?}`,是 download 的对偶:
  - 任意版本均可导出(无发布门控,与 download 一致)。
  - 目标校验:数据源须存在且 `type == s3`(否则 404/400)。
  - 成员逐个**读源→写目标**:s3/托管成员走 `cached_bytes`(命中物化缓存免重复下载)、
    本地成员读盘;统一 `upload_object` 上传到目标 `bucket/[prefix/]文件名`(同名加序号去重)。
  - **红线**:导出目标 ==(同数据源+同桶+同 key)托管源对象时 **400 拦截**,绝不回写源
    (呼应 #18「外部托管不破坏源」)。
  - 返回 `{exported, target}`。
- **前端**:`exportVersionToS3` api + 详情页「导出到 S3」ModalForm(选 s3 数据源 → 列桶 → 填前缀)。
- **测试**:`tests/unit/test_export_s3_route.py`(6 用例):缺版本 404 / 草稿不再门控(200)/
  目标非 s3 400 / 本地成员上传 happy path / 缺本地文件 410 诚实回因 / 回写源红线 400。
- **fail-loud**:下载(`_download_zip`)/导出全部成员被跳过时,不再笼统报「无可用成员」,
  而是带原因(本地文件不存在+路径 / S3 拉取失败+异常),诊断数据位置问题用。

## 4. 仍欠(不阻断主干闭环,独立排期)

| 项 | 闭合什么 | 量级 |
|----|----------|------|
| ⑤ 数据标注引擎(后端路由+ORM+迁移、标注工作台、标注算子目录) | ④→⑤→⑥ 标注节点 | XL |
| 血缘图遍历端点 + `/lineage` 可视化(produced_by_job_id↔job_inputs 递归) | #11 血缘节点 | L |
| 质量 job 异步化(对齐加工后台执行,大版本不阻塞 HTTP) | ③ 可用性 + 低质反馈边体感 | M |
| manifest 版本不可变守卫(原地改写已发布版本 → 409 或派生新版本) | #11 版本不可变 | S |
| cron 调度执行引擎 + HDFS/API 采集连接器 | 接入侧扩展 | L |

> 取舍结论:**优先导出**(让数据真能被取走,ROI 最高);标注引擎 effort XL、不阻断主干,延后独立排期。
