# 09 · 分类(Category)管理设计(收编 BCC「分类管理」)

> 关联:需求 #15(分级分类:敏感级别 × 业务类型双维度)的缺口补全——清单原话"缺受控标签库/树与按分级分类筛选";并补 #16 检索的分类维度。
> 来源:BCC 平台「数据接入」调研(`docs/research/bcc-数据接入调研.md` §4.1 分类管理)。
> 与 #14 区分:**分类(category)= 单选分组**;**#14 标签(tags)= 多标签**,是另一独立功能,不在本范围,互不冲突。
> 状态:✅ 已实现并部署 10.60.1.60(2026-06-15,迁移 `0009_categories`,alembic head 现为 `0009`)。形态:**补能力(不改 IA)· 扁平 · 跨实体共享 · 单选**。后端 122 测试通过;E2E 已验证创建/打分类/列显示/筛选/删除引用守卫(409)/删空(200)/RBAC(匿名 401)全链路。

## 1. 范围

**做**:引入一套**受控的扁平分类库**(BCC「分类管理」同形:名称 + 备注 + 创建人 + 时间),跨实体共享;`数据源` / `采集任务` / `数据集` 各可单选挂一个分类;三处列表支持**按分类筛选** + 列内显示分类;分类库提供 CRUD 管理界面。把数据集现有的**自由填 `business_category`** 收口为从分类库取值的受控单选。

**不做(YAGNI / 划清边界)**:
- 不做层级/树形分类(本期扁平单层)。
- 不做多标签(那是 #14,独立功能)。
- 不动 IA / 菜单结构(保留现有 `/ingest` 机制优先布局)。
- 不引入 BCC 的「文件管理」文件系统与「文件复用」导入(那是更重的全面收编档,本期不取)。
- 分级 `sensitivity_level` 维持现状(已是枚举 public/internal/confidential),本期不改造。
- 分类批量删除留后(先做单删 + 引用守卫)。

**复用既有**:数据集 `business_category` 字段语义(#13/#15)——由自由填升级为受控单选,不新造平行概念。

## 2. 后端

### 2.1 数据模型
- **新表 `categories`**:
  - `id`:主键,形如 `cat-` + 6 位 hex(沿用本仓库 id 约定)。
  - `name`:String,**唯一**,非空。
  - `note`:String,可空(备注)。
  - `creator`:String,非空,默认 `admin`。
  - `created_at`:server_default now。
  - 扁平单层,无 `parent_id`。
- **三实体加 `category_id`**(String,**nullable**,纯引用,沿用本仓库无-FK 约定,与 `dataset_id`/`source_datasource_id` 同款):
  - `datasets.category_id`
  - `datasources.category_id`
  - `ingest_tasks.category_id`
- **用 id 引用而非名字**:改分类名时三处引用天然同步,无需级联 UPDATE。

### 2.2 迁移 0009(down_revision=`0008_hosted_s3`)
1. 建 `categories` 表。
2. `datasets` / `datasources` / `ingest_tasks` 各加 `category_id`(nullable)。
3. **数据集分类收口**:
   - 从 `SELECT DISTINCT business_category FROM datasets WHERE business_category IS NOT NULL AND business_category <> ''` **播种** `categories`(逐条建 `cat-*`,creator=admin)。
   - 回填 `datasets.category_id`:按名字匹配把 `business_category` 映射到对应 `categories.id`。
   - **删除 `datasets.business_category` 列**。
4. downgrade:加回 `business_category`(从 category_id 反查名字回填)、删三个 `category_id`、删 `categories` 表。

### 2.3 分类 CRUD API
- `GET /categories` → `[{id,name,note,creator,createdAt,usageCount}]`。`usageCount` = 三实体引用该分类的总数(供删除前提示与管理页展示)。
- `POST /categories` body `{name, note?}` → 创建;`name` 重复返回 409。
- `PATCH /categories/{id}` body `{name?, note?}`(exclude_unset)→ 改名/改备注;改名撞已有名 409。
- `DELETE /categories/{id}`:
  - 若 `usageCount > 0` → **409** `{success:false,message:"分类正被 N 处引用,无法删除"}`(不孤儿化)。
  - 若空 → 删除成功。
- **权限**:以上 CRUD 全部 `require_admin`(受控词表属管理动作)。
- schema:`app/schemas/category.py`——`CategoryCreate` / `CategoryUpdate` / `CategoryRead`(`createdAt`/`usageCount` 走 alias 驼峰,与全仓 by_alias 约定一致)。

### 2.4 给实体打分类 + 筛选
- **写入**(接收 `categoryId`,可空;权限跟随各实体自身的新建/编辑权限,不额外加 admin):
  - 数据源 create / PATCH(`app/api/v1/datasources.py`)。
  - 采集任务 create(`app/api/v1/ingest_tasks.py`)。
  - 数据集元数据 PATCH(`app/api/v1/datasets.py`,替换原 `business_category` 入参为 `categoryId`)。
  - 上传 `POST /datasets`(multipart 增 `categoryId` 表单字段,可空)。
  - 托管 `POST /datasets/host-s3`(可选带 `categoryId`)。
- **筛选**(列表查询增 `categoryId` 过滤,**同时作用 count + list**,与现有 name/dataType 过滤同款):
  - `GET /datasets`(当前仅 name/dataType——本次补 categoryId,填 #15/#16 缺口)。
  - `GET /datasources`。
  - 采集任务列表 `GET /ingest-tasks`。
- 列表/详情读模型(DatasetRead / DataSourceRead / IngestTaskRead)增 `categoryId?` 与 `categoryName?`(后者由 join/批量取名回填,避免前端二次请求;批量查一次 categories 字典即可,无 N+1)。

## 3. 前端

- **「分类管理」抽屉组件**(antd,BCC 同形):分类列表(名称/备注/创建人/创建时间/用量)+ 新增/编辑/删除;删除被引用项时按后端 409 提示用量。**三个列表工具栏共用同一组件入口**(`<Access canAdmin>` 门控按钮)。
- **三个列表**(`ingest/datasources`、`ingest/tasks`、`datasets/list`):工具栏加「分类」筛选下拉(选项来自 `listCategories`);表格加「分类」列(显示 `categoryName`)。
- **表单**:上传 / 新建数据源 / 新建采集任务 / 数据集元数据编辑——分类做成 `ProFormSelect`(`request` 拉 `listCategories`)。数据集那个由**自由填升级为下拉**。
- `api.ts` + `typings.d.ts`:`listCategories` / `createCategory` / `updateCategory` / `deleteCategory`;`Category` 类型(`id/name/note/creator/createdAt/usageCount`);`Dataset`/`DataSource`/`IngestTask` 增 `categoryId?`+`categoryName?`;各 list params 与 create/update params 增 `categoryId`。
- **不编辑** `src/services/ant-design-pro/`(自动生成)。

## 4. 操作矩阵

| 操作 | 权限 | 说明 |
|---|---|---|
| 浏览分类 / 按分类筛选 | 所有登录用户 | 三列表筛选下拉 + 列展示 |
| 给实体选分类(建/编辑时) | 跟随该实体写权限 | 单选,可不选(null) |
| 新建 / 改名 / 改备注 分类 | admin | `require_admin` |
| 删除分类 | admin | 被引用 → 409;空 → 成功 |

## 5. 不破坏现网 / 风险

- 迁移 `0009` 仅加表 + 加列 + 数据迁移 + 删一列;**播种保证旧自由填值不丢**(变成受控分类项,数据集仍挂着)。
- 删 `business_category` 列会动 #13 元数据编辑表单一个字段(自由填 → 下拉)——属 **#15 计划内升级**,非范围蔓延;同步改 `DatasetUpdate` schema 与详情抽屉表单。
- `categoryId` 全程 nullable:存量数据 / 不选分类的实体不受影响。
- 单选语义,与 #14 多标签零冲突;分级维度不动。
- 删除守卫双层:后端 409 + 前端按用量提示,杜绝产生悬空引用。

## 6. 验收

- 建分类(金融风控 / 营销活动)→ 新建数据源、采集任务、上传数据集时各选一个 → 三列表都能**按分类筛选** + 列里显示分类名。
- 改某分类名 → 三处引用**同步显示新名**(id 引用天然同步,无需手动刷)。
- 删被引用的分类 → **409 + 用量提示**;删空分类 → 成功。
- 旧有自由填 `business_category` 值 → 迁移后成为分类库条目,且原数据集仍挂着它。
- 受管/托管数据集、既有数据源/采集任务全流程回归不受影响(categoryId 可空)。
- 非 admin 用户:看得到分类筛选、能在建/编辑时选分类,但分类管理(增改删)入口不可见 / 调用 403。
