# 10 · 文件管理(MinIO 对象存储管理)设计

> 关联:收编 BCC「文件管理」(`docs/research/bcc-数据接入调研.md` §六),但**仅管理平台 MinIO 对象存储**(不做 BCC 的 用户/项目/共享 ACL 目录)。复用 #18 已搭的 MinIO(60)+ `external_store`。
> 状态:✅ 已实现并部署 10.60.1.60(2026-06-15,无迁移)。**完整文件管理(浏览+上传+新建文件夹+删除+下载/预览)· 专用 `STORAGE_MINIO_*` 配置 · 写仅 admin/浏览所有人 · 新一级菜单「文件管理」· 删除软保护(拦截被托管引用的对象)**。后端 125 测试通过;E2E 真连验证:列桶/建文件夹/上传/列目录(已修复"列自身目录幻影子目录"bug)/下载 presigned/递归删/匿名 401 全链路;UI 已渲染真实 MinIO 对象。

## 1. 范围

**做**:一个管理**平台 MinIO**(10.60.1.60 那台)的文件页——选桶 → 面包屑路径(key prefix 当"文件夹")→ 列文件夹 + 对象 → **上传 / 新建文件夹 / 删除 / 下载 / 预览**。S3 无真实目录,"文件夹" = 带 `/` 结尾的 key 前缀(列举用 delimiter 分组,新建用零字节 `prefix/` 标记)。

**不做(本期)**:
- 接入复用(BCC「文件管理文件上传」——从文件管理选文件登记成数据集)留下一期。
- 多 MinIO / 跨存储后端、对象版本化、ACL/权限分级目录(用户/项目/共享)。
- 不动 #18 既有逻辑;无数据库结构变更、**无迁移**。

**复用既有**:MinIO(60,#18 已部署,桶 `datasets`/`uploads`,账号 adpadmin)、`external_store.client_for`。

## 2. 后端

### 2.1 配置(`app/core/config.py`)
新增字段(pydantic-settings,env `STORAGE_MINIO_*`):
- `storage_minio_endpoint: str | None = None`(如 `http://10.60.1.60:9000`)
- `storage_minio_access_key: str | None = None`
- `storage_minio_secret_key: str | None = None`

未配置 → 文件管理接口统一返回 `503 {success:false,message:"平台存储(MinIO)未配置"}`,不抛 500。

### 2.2 `external_store.py` 新增(复用 `client_for`,全部 `asyncio.to_thread`)
- `platform_config() -> dict`:从 settings 拼 `{endpoint, accessKey, secretKey}`;缺配置抛 `ExternalStoreError`。
- `list_dir(config, bucket, prefix) -> {folders: [name], files: [{key, name, size, lastModified}]}`:`client.list_objects(bucket, prefix, recursive=False)`,`is_dir` 项归 folders、其余归 files;上限沿用 `_LIST_LIMIT`。
- `upload_object(config, bucket, key, data, length, content_type)`:`client.put_object`。
- `create_folder(config, bucket, prefix)`:put 零字节对象 `prefix.rstrip('/') + '/'`。
- `remove_object(config, bucket, key)`:`client.remove_object`。
- `remove_prefix(config, bucket, prefix) -> int`:列举(recursive)+ `remove_objects`,返回删除条数。
- `presigned_get_url(config, bucket, key, expires=600) -> str`:`client.presigned_get_object`(URL 主机即 MinIO endpoint,浏览器可直连 60:9000 下载)。

### 2.3 新路由 `app/api/v1/files.py`(挂 `/api/v1`,tag `files`),注册进 `app/main.py`
**读(所有登录用户)**:
- `GET /files/buckets` → `{data:[name], success}`。
- `GET /files?bucket=&prefix=` → `{data:{folders, files}, success}`。
- `GET /files/download-url?bucket=&key=` → `{data:{url}, success}`(presigned)。
- `GET /files/preview?bucket=&key=&limit=` → 复用 `head_records` → `{data:{columns, data, total?}, success}`(jsonl/csv 等可解析格式;不可解析返回提示)。

**写(`require_admin`)**:
- `POST /files/upload`(multipart:`bucket`、`prefix`、`file`)→ put 到 `bucket/{prefix}{filename}` → `{data:{key}, success}`。
- `POST /files/folder`(`{bucket, prefix, name}`)→ `{success}`。
- `DELETE /files/object?bucket=&key=` → **删除软保护**(见 2.4)→ `{success}`。
- `POST /files/delete-folder`(`{bucket, prefix}`)→ 软保护 → 递归删 → `{data:{deleted:n}, success}`。

错误经 `ExternalStoreError` 兜底为 `{success:false,message}`(4xx);`require_admin` 抛 401/403。

### 2.4 删除软保护(数据安全)
平台 MinIO 的 `datasets` 桶里可能有 **#18 托管数据集**引用的对象(`dataset_versions.origin='hosted'`,`storage_uri='s3://{bucket}/{key}'`)。删除前查引用:
- 删单对象:`SELECT 1 FROM dataset_versions WHERE origin='hosted' AND storage_uri = 's3://{bucket}/{key}'` 命中 → `409 {success:false,message:"该文件被 N 个托管数据集引用,无法删除"}`。
- 删文件夹:`... AND storage_uri LIKE 's3://{bucket}/{prefix}%'` 命中 → `409`(提示引用数)。
- 仅读 `dataset_versions`,不改它;与 #18「删源禁止」精神一致(这里是平台自有 MinIO,允许删未被引用的对象)。

## 3. 前端

- **新一级菜单「文件管理」**:`config/routes.ts` 加 `{path:'/files', name:'files', icon:'folder', component:'./files'}`;各 locale `menu.files = 文件管理`(至少 zh-CN/en-US,余者跟随)。
- 页 `src/pages/files/index.tsx`:
  - 桶下拉(`listPlatformBuckets`)+ 面包屑路径(prefix 分段,可点回退)。
  - ProTable:**文件夹在前**(名称带 📁,操作=进入→换 prefix),再列对象(名称/大小/修改时间,操作=下载/删除);`request` 调 `listFiles({bucket, prefix})`。
  - 工具栏:**上传**(antd `Upload` → `POST /files/upload`,带当前 bucket/prefix)、**新建文件夹**(弹框输入名 → `createFolder`)——均 `<Access canAdmin>` 门控。
  - 下载:`getFileDownloadUrl` 拿 presigned → `window.open`。删除:`Popconfirm`;**删文件夹**强二次确认(文案提示递归 + 条数)。被软保护拦截(409)时透出后端 message(api 用 `skipErrorHandler`)。
- `api.ts` + `typings.d.ts`:`listPlatformBuckets / listFiles / uploadPlatformFile / createFolder / deleteFileObject / deleteFolder / getFileDownloadUrl / previewFile`;类型 `FileEntry`(`key/name/size/lastModified`)、`FileListResult`(`{folders:string[], files:FileEntry[]}`)。
- **不编辑** `src/services/ant-design-pro/`。

- `deploy/.env`(+`.env.example`+`README.md`)加:`STORAGE_MINIO_ENDPOINT=http://10.60.1.60:9000`、`STORAGE_MINIO_ACCESS_KEY=adpadmin`、`STORAGE_MINIO_SECRET_KEY=adpMinio#2026`。

## 5. 权限矩阵

| 操作 | 权限 |
|---|---|
| 列桶 / 列目录 / 下载 / 预览 | 所有登录用户 |
| 上传 / 新建文件夹 / 删除对象 / 删除文件夹 | admin(`require_admin`) |

## 6. 测试

`backend/tests/test_files.py` 真连 60 MinIO(socket 探测不可达则整模块 skip,同 `test_external_store`):
- 流程:建文件夹 → 上传对象 → `list_dir` 可见(folders 含新建、files 含上传)→ download-url 返回 presigned → 删对象 → 删文件夹(递归)成功。
- 软保护:对一个被 hosted 版本引用的 key 删 → 409。
- RBAC:非 admin 上传/删除 → 403;匿名 → 401;非 admin 列目录 → 200。
- 用例自建前缀(uuid)隔离 + 用后清理,绝不碰 #18 既有对象。

## 7. 风险

- presigned URL 暴露 MinIO endpoint(60:9000)给浏览器——演示环境可接受;有效期 10min。
- 递归删文件夹是破坏性操作:admin-only + 强二次确认 + 软保护(被托管引用则拦)。
- 平台 MinIO 与 #18 共用同一物理 MinIO;软保护覆盖"删到托管引用对象"这一交叉风险,其余非引用对象删除自负。
- 未配 `STORAGE_MINIO_*` 时功能整体不可用但不报 500(503 明确提示),不影响其它模块。

## 8. 验收

- 配好 env 后:文件管理页列出 `datasets`/`uploads` 两桶 → admin 新建文件夹、上传文件、进目录、下载、删除全可用;删被托管引用的对象被 409 拦截。
- 非 admin 登录:只见浏览/下载/预览,写操作入口隐藏且直接调 API 返回 403;匿名 401。
- 既有 #18 托管 / 数据集 / 数据源全流程不受影响。
